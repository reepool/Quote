## Context

M1—M3已有业务闭环，但M4长期逐对发现并修复缺陷。历史累计约70家公司分属不同代码版本，不能当作同版未见验证。当前v60另有在途正式交付，本change只确定后续验收合同，不修改在途材料。

## Goals / Non-Goals

Goals：明确12/20/100数量、一次S2新20家确认上限、首发质量与补救后可用率、不可外放错误、有限补救和唯一进度入口。

Non-Goals：业务代码实现、执行本轮新样本、重跑历史70家公司全部事实、审核v60、自动评分平台、行业增强、生产/DCF/交易启用。

## Decisions

1. 以`docs/development/company_profile_acceptance_program.md`为人类可读计划和唯一进度表，OpenSpec新增规范固定必要约束。产品总需求和A/B流程只引用，不复制另一份状态表。
2. 固定样本数、各层和版本，首发完成前不逐家公司调参。已有样本用于12家回归；未见验证最多两组各20家；100家另取，防止用累计修复数代替迁移能力。相比无限两家循环，到数量即能明确判失败。
3. 公司分可用/限用/隔离。要求零已知底线错误外放，允许限量非核心缺项；相比全字段100%避免阻塞研究使用，相比平均准确率单门槛避免主体/核心金额错误被稀释。
4. 首发≥90%公司可用、补救后≥95%，核心召回宏平均≥95%、已审准确率≥99%；各层另有底线。核心/高风险全查，补充每家至少20个实际唯一对象，明确为已审/抽样精度，不外推未核事实全对。
5. 单家公司额外业务重试1次、额外人工补救30分钟；一组共性修复最多2次且不得绕开单公司上限。首发门槛未过不能靠同源修复改写。S2至多再用一次新20家证明；S3到100家即裁决，不增分母稀释失败。
6. 计划不新增机器字段或平行owner。分级先体现在既有交接/覆盖信息；若现有读取不能隔离错误对象和依赖答案，后续任务沿原接受/投影owner局部修复后才可研究交付，不能以文档承诺冒充已实现。

## Risks / Trade-offs

- 小样本不能证明全市场可靠 → 报告分层、数量和审查限制，生产/规模权限不变。
- 只测制造服务会掩盖金融等缺口 → 固定金融、综合披露及交易所配额；来源不足报告未准备好，不默默替换范围。
- 人工审查膨胀 → 核心/风险全查、补充冻结抽样；复用直接回归和现有证据，不建立新平台。
- 通过修复、删行或换公司美化成绩 → 原始首发、错误候选、隔离和修复分列；名单失败仍计分母，全部实际输出可被抽中或风险扩查。
- 工作区存在并行B交付 → 只修改本人规划和导航文件，提交只含本人路径，不操作既有暂存材料。

## Migration Plan

计划制定后，下一次A审核v60仍按原354条件/逐对象100%合同；通过后在新执行卡显式接续本计划，先S1再S2，S2通过后再S3。每卡独立冻结实际来源/代码/预算。回退只停止未来执行，原记录保留；不迁移数据库、不改默认身份、不追溯成绩。
