## Context

华能 2025 年报第 16 页"主营业务分地区情况"表在解析文本中折行为：`中国境内 202,761,140,328 165,457,723,992` 换行 `18.40 -6.29 -10.66 增加 4.00`。`_is_enumerated_revenue_class` 用 `^\d+[、.．]` 匹配，把"18."当编号，先复位组合表分组并清空单位；`_parse_segment_row` 用同样的编号模式剥前缀，把余下的"40 -6.29 …"解析成名为"40"的分部行。于是导出出现 `segment:revenue_composition:40` 假分部，"中国境外"行失去单位、其 `operating_revenue` Measurement 因无单位而不生成。

主体句边界：`_MAIN_BUSINESS_SENTENCE` 是 `公司的主要业务是[^。]{8,500}`，没有左边界，"子公司的主要业务是"中的子串会命中，子公司句子被当成公司主营。

单位绑定：`column_unit` 在 `source_delivery_repair` 下只要摘要含"人民币百万元"就全段生效，独立次表打开时若没有自己的单位声明，会继承首表的百万元。

上一轮已核实成立的部分——主营全文、煤炭 1.86 亿吨、电热联合占比 96.37%、石化收入栏目单位与事业部内部销售——本轮必须原样保留。煤炭保持 ambiguous 符合现行合同，不在本卡扩目录。

## Goals / Non-Goals

**Goals:**

- 小数续行不再成为分部行；"中国境外"恢复单位"元"和收入 Measurement；假分部从查询和导出消失。
- 合法编号收入行（含机场父子收入）不受影响。
- "子公司的主要业务是"不再成为公司主营句。
- 首表的百万元不再流入无单位的独立次表；组合表组内共享单位的行为保持。
- 新身份 `revenue_sentence_repair=v9` 累积 v8 全部修复，在独立目录重跑两份冻结年报并完成全覆盖复核。

**Non-Goals:**

- 不回写 v7 的 2/11、v8 的 12/12 或 `expansion_gates_met=true`。
- 不预填分数，不放宽门槛：召回 100%、准确率 100%、关键数字错误 0、耗时不超过 300 秒。
- 不冻结下一组未见样本，不扩商品目录，不授权生产或规模质量。

## Decisions

1. 新标记是 `revenue_sentence_repair=v9`。它继续包含 v8 的全部答案、角色与来源修复。
2. 编号剥除只在编号点后跟非数字时生效（`[、.．](?!\d)`）。"18.40""-6.29"一类小数续行因此既不匹配枚举收入类，也不被剥成行名；纯数字或比率续行因行名含小数点或非数字 token 不满足行解析，不再生成分部。
3. 表内单位绑定按表界定：组合表组（一次"分行业、分产品、分地区"声明）内的子表继续共享组内单位；独立打开的表若没有自己的单位声明，单位回到未知，不继承前表。
4. 公司主营句要求"公司的主要业务是"前不是"子"，即排除子公司主语；母公司、本公司措辞按各自原样处理，不在本卡扩展。
5. 复核分母从原文独立重建，覆盖重要披露与明示商品角色；分子覆盖实际交付的答案、角色、Segment 与 Measurement，重复披露只计入准确率，不重复计入召回。

## Risks / Trade-offs

- [编号判定收紧后漏掉合法编号行] → 机场父子收入与既有编号收入回归必须原样通过。
- [单位界定改动影响石化百万元表] → 石化四构成与单位断言保留为回归。
- [重跑覆盖面变大后暴露新缺陷] → 如实记录新观察，不在本卡内改判据。

## Migration Plan

先做从解析到导出的定向测试（真实表格回归），再以 v9 身份隔离重跑两份冻结年报，最后按原文重建召回并完成全覆盖复核。失败不回滚 v7、v8 的历史观察。
