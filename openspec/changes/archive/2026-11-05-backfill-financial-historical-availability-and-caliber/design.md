# Design: 回填财报历史可得性日期并量化历史批次口径差

## 1. 背景与证据基线

全部证据取自 2026-11-03 三季报抽查与历史复检（同会话）：

| 事实 | 数值 |
| --- | --- |
| `financial_facts` 缺 `publish_date`/`data_available_date` | 54,389 / 66,134 行（82%），集中于 2023Q4–2026Q1 十个季度，每期 98–99% |
| `financial_source_files` 目标区间带 `published_at` | 604 / 62,235 行（472 对）≈ 1% |
| 归档事件（59,232 行）目标区间带 `announcement_time` | 2 条 |
| 口径差抽样（2025-09-30，n=300） | 4 只 revenue 不一致（1.3%），营业总收入 vs 营业收入模式 |
| `total_assets` NULL（2024–2025 Q1/Q3） | 289 行，其中 40 行数值层有值 |
| 历史事件陈旧 `mapping_catalog_empty` reason | 2,010 条（状态均正确） |

既有资产：`research/financial_available_date_backfill.py`（证据驱动、幂等、
支持 dry-run）、公告采集服务（市场级分类扫描 + 标题推期
`infer_report_periods_from_title`）、`announcement_audit` 表、定向
reconciliation（`target_symbols`）。本 change 不新建任何平台。

## 2. 决策记录

### D1 证据进货顺序：本地 → 勘察 → 法定兜底

- **备选 A（逐对网络查询）**：5,500 × 10 = 55,000 次请求，量大且重复触发
  源站反爬——否决。
- **备选 B（仅法定截止日）**：零网络、PIT 安全，但全部行都退化为保守上界，
  研究精度损失不可接受——仅作兜底层。
- **采纳**：三级瀑布。本地证据（含新增两表源）先扫；缺口走市场×季度窗口
  公告流勘察（一次请求 ≈ 30 条，全区间数千请求级）；仍缺才落法定截止日。
  预期大头由勘察层解决，法定兜底限于退市/特殊行。

勘察窗口的日期边界按披露季定义：每期窗口 = 法定披露季起点至截止日
+ 延期尾窗 60 天（Q1→1/1–4/30+60d、H1→7/1–8/31+60d、Q3→10/1–10/31+60d、
年报→次年 1/1–4/30+60d），覆盖延期披露公司；证据仅接受定期报告类别公告
（标题推期同限制），业绩说明会预告等更早事件不得进入证据（防未来函数）。
三市场 × 10 个报告期 ≈ 30 个窗口、预期审计行数约 16 万，`announcement_audit`
按现状追加，无独立清理机制的新建。

### D2 勘察写 `announcement_audit`，不写事件状态

11-03 修复期间事件表曾被手工裁剪 5.9 万→1.2 万行以解决膨胀。历史勘察若走
事件状态路径，会重新注入约 5.5 万条历史事件，重演膨胀。专用
`purpose_key='historical_disclosure_date_survey'` 写 `announcement_audit`
（该表本就为"选中公告留痕"设计），回填模块证据加载器增加一个读取源即可。
事件状态表零触碰是硬约束，写入验收。

### D3 网络勘察执行约束（403 事故教训固化）

2026-11-03 18:12：独立 `python -I` 进程全市场 data20 抓取，headed Chrome
引导失败（no_sandbox）→ 裸 HTTP 批量 → 三交易所 403。本 change 将教训写
为执行合同：

- 启动探针：一次有界单页请求确认公告源健康，失败即拒绝扫描（实现注记：
  403 事故根因在 data20 报表端点的 5,500+ 逐家批量，公告检索端点在 11-04
  全量勘察中独立进程 + 温和限速下 30/30 窗口零 403，故 Chrome 栈要求划归
  报表/文档端点，公告勘察由探针 + 限速 + 停窗覆盖）；
- 限速温和（默认请求间隔 ≥ 1s，可配置），窗口间留间隔；
- 按市场×季度窗口断点续跑，连续 403/限流即停窗等待下个调度窗口；
- 推荐宿主：现有调度器手动触发（`run_job_now` 或 worker 侧入口），不写
  新的独立常驻进程。

### D4 法定截止日兜底的语义

A股法定披露截止：Q1→4/30、H1→8/31、Q3→10/31、年报→次年 4/30。兜底值
满足"不早于真实可得"（最晚合法披露日），PIT 安全方向正确；lineage 记
供研究侧区分（实现核实：模块既有标记为 `source='estimated_statutory_deadline'`/`quality='estimated'`，spec 对齐该既有标记，不新造标记）。两个关键语义：

- **兜底只填 `data_available_date`，`publish_date` 保持 NULL**——法定截止
  日是保守上界而非披露事实，写入事实字段等于伪造披露日；既有模块对
  publish_date 本就只在 observed 质量时填充（`financial_available_date_
  backfill.py` 现行为），新增勘察源按 observed 等价对待。
- **实测日允许晚于法定截止日**——延期披露是真实存在（如 2026Q3 上海银行、
  华发股份延期公告），实测晚于截止日不是校验违例；硬性校验只有两条：
  `data_available_date ≥ 报告期期末`、兜底行 == 法定截止日。实测超截止日
  60 天以上进异常清单人工复核，不阻断验收。

### D5 口径差：量化 MUST、重派生是决策门

量化报告是本 change 的交付物；重派生（用现行 v6 管道重跑历史行）改变研究
侧可能已消费的历史数值，且"营业总收入对控股公司更合理"存在真实口径之
争——决策归 owner，未经决策不执行。量化报告按分期×分字段给出差异率、
典型样本与科目归类，阈值默认 0.5%（可由 owner 调整）。

### D6 零星项与边界

- 金刚光伏：定向 reconciliation `target_symbols=['300093']`，2 分钟级。
- 40 行 total_assets：本地 SQL 回填（equity 回填同模式，只填 NULL）。
- 249 行无源 NULL：先查 `financial_statements_raw` 有无源文件可重解析；
  无则接受并记录——不为 <2% 的历史季报解析缺口重写解析器。
- 2023Q4 前边界：系统滚动窗口即 10 季（2024Q1 起），2023Q4 全量覆盖为基
  线；扩产无当前消费方（基础设施准入测试不通过），文档声明即可。

## 3. 执行计划（三张卡，可独立排期）

```
M1 本地小卡（无网络，可随时）
   口径量化脚本 + 报告落盘 → 40 行 TA 回填 → 金刚光伏定向收编
   → 回填模块证据源扩展（两本地表）+ dry-run 试跑
M2 网络勘察卡（安静窗口，调度侧执行）
   勘察脚本/入口（D2/D3 约束）→ 分窗执行 → announcement_audit 落库
M3 回填与验收卡（本地为主）
   回填模块全量跑 → 法定兜底 → 覆盖率/PIT/抽样三类验证
   → mapping_catalog_empty 清零确认（窗口内周日全量 + 2023Q4 定向刷新）
   → 口径量化报告提交 owner 决策（重派生留待决策后另行排期）
```

M1 与 M2 可并行；M3 依赖 M1（证据源扩展）与 M2（勘察证据）完成。

## 4. 兼容性与生产不变量

- 表结构零变更（只 UPDATE 空值列）；不触发 change watermark（不动
  `row_hash`/`updated_at`，与 equity 回填同模式，已验证无下游级联）；
- 当季管道（2026-06-30 起）行为不变；
- `financial_available_date_backfill` 既有 CLI 参数与行为向后兼容，新增
  证据源是纯增量；
- 运行中调度器进程不受 M1/M3 本地操作影响（写路径与夜间任务不同表不同列，
  21:45/周日窗口避开即可）；
- 全部临时产物按 §2.3 入 QuoteBak，验收证据（量化报告、覆盖率报告、抽样
  核对表）持久化 `docs/development/`。

## 5. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 勘察触发源站封禁（403 重演） | D3 执行合同 + 窗口断点 + 停窗等待；勘察用公告接口（11-03 实测封禁期间仍 200） |
| 勘察标题推期误判（如"业绩预告"误入） | 复用增量同步同款标题分类；勘察只取"定期报告"类别；证据合并层再按类别过滤一次；抽样核对含此项 |
| 更早的非定期公告误当可得日（未来函数） | D1 证据类别硬限制：仅定期报告公告可作证据；spec 有对应场景与单测 |
| 法定截止日对延期披露公司偏晚 | 兜底层只影响该类行且方向保守（晚于真实），研究侧可按 quality 过滤；实测日晚于截止日属真实情况不视为违例（D4） |
| 回填与夜间任务并发写 | M3 安排在日间安静窗口；回填仅 UPDATE 空值，幂等可重跑 |
| `announcement_audit` 追加约 16 万勘察行 | 按现状表追加，无新建清理机制；验收报告记录行数量级供后续治理决策 |
| 口径量化全表比对耗时（数值层 3,000 万行） | 复用 equity 回填的临时聚合表模式（单次扫描 + JOIN），预期分钟级 |
