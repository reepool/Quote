## Context

v10 复核的是 `600011.SH` 和 `600028.SH`。历轮计划已观察 `600007.SH`、`600008.SH`、`600009.SH`、`600010.SH`、`600019.SH`、`600022.SH`，更早交付与修复用过 `600000.SH`、`600004.SH`、`600006.SH` 和 `302132.SZ`。默认冻结只看当前身份的已交付记录，盖不住这些公司。v10 身份已累积到 `revenue_sentence_repair=v10`，复核口径已在上一卡固定：不同栏目分别判断、跨页重述只计一次、Measurement 重复不增召回但逐条核对。

## Goals / Non-Goals

**Goals:**

- 这次冻结显式排除上述全部已观察公司，显式包含 `600011.SH` 和 `600028.SH`。
- 计划重复读取一致，两家都是未见样本，且一服务、一制造。
- 运行、查询、导出使用完整 v10 身份和独立目录。两家进入同一观察。
- 复核从两份新年报逐条记分，继承固定口径。合法负例保留检查范围。失败保持失败。

**Non-Goals:**

- 不改同身份默认排除。
- 不预填分数，不回写 v9 的 20/22 或 v10 的 26/26、43/43。
- 不授权生产，不声明规模质量。
- 不做行业包、六章包或框架整理。
- 本轮未通过前不安排再下一组。

## Decisions

1. 已观察集合是历史集合与历轮计划集合的并集：`600000.SH`、`600004.SH`、`600006.SH`、`600007.SH`、`600008.SH`、`600009.SH`、`600010.SH`、`600011.SH`、`600019.SH`、`600022.SH`、`600028.SH`、`302132.SZ`。冻结调用传入这个集合。
2. 新目录是 `reports/m4_v10_unseen_small_batch`。处理身份是默认身份加上 `revenue_sentence_repair=v10`。
3. 运行顺序按计划中的服务公司、制造公司。查询和导出选择同一身份；失败耗用计入共享预算，第二家用剩余额度。
4. 召回清单从两份新年报的原文独立建立，继承固定口径：不同栏目/dimension 的来源行分别判断，同一事实跨页重述只算一次，同一来源的 Segment 与 Measurement 重复数值不增加召回，六维答案、角色和每条实际接受事实逐条对应。
5. 无本公司商品角色的公司，独立核对后记为有检查范围的负例，不算漏召回。

## Risks / Trade-offs

- [漏掉刚跑过的两家] → 排除集显式包含 `600011.SH` 和 `600028.SH`，并用重复冻结核对。
- [新年报披露形态没有覆盖形态] → 选样仍按计划顺序取第一家合法候选，无合法候选则拒绝记录计划。
- [服务公司没有商品角色] → 独立核对后记为有检查范围的负例。

## Migration Plan

先冻结并核对计划（历史文件字节不变），再运行、查询、导出，最后独立复核计分。失败不回滚已有观察。
