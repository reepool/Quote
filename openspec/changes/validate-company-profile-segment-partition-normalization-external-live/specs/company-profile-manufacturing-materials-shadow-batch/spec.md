## ADDED Requirements

### Requirement: Sandbox DNS failure receives one externally authorized new-identity validation

When the prior bounded segment-normalization validation produced no upstream response and preserved sandbox `dns_failure` connect diagnostics, the system MUST permit exactly one new-identity repetition from the sandbox-external network path. The repetition MUST bind the prior result, immutable source batch, exact two prepared scopes, implementation hashes, Gemini route, budgets, deadline, output absence, and research-only boundary before provider construction.

#### Scenario: External validation inputs match

- **WHEN** the predecessor failure, source hashes, exact cases, implementation hashes, route, budgets, authorization target, and output-absence conditions match the contract
- **THEN** the existing Stage 5 application service executes both frozen scopes under the sole new identity
- **AND** only task-required request content derived from those scopes is transferred to `scorpio.reepool.com`.

#### Scenario: An external validation input drifts

- **WHEN** any bound predecessor, source, scope, implementation, route, budget, target, or output condition differs
- **THEN** execution fails before provider construction
- **AND** no replacement scope, model, or relaxed contract is inferred.

### Requirement: External validation remains isolated and research-only

The result MUST preserve source-bound extract/verify output or typed failures for both cases. It MUST NOT modify either the historical batch or predecessor validation, recompute twenty-report readiness, splice candidates, automatically launch a cohort replay, or grant production authorization.

#### Scenario: Both cases resolve

- **WHEN** both scopes complete with accepted source-bound rows and without their targeted normalization failures
- **THEN** the result MAY recommend separately evaluating one later full-cohort replay
- **AND** it MUST retain `production_authorization=not_authorized`.

#### Scenario: A case remains blocked or fails execution

- **WHEN** either case retains a substantive semantic blocker or ends in a transport, deadline, parse, schema, or provider failure
- **THEN** the exact result is retained under the sole identity
- **AND** no tuning, model substitution, or second provider run occurs in this change.
