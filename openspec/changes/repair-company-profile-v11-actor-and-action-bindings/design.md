## Context

`_activity_object_clauses` 把"主要产品为"捕获组按顿号逐项拆开,"旋挖钻机,用于市政建设、公路桥梁……防渗护坡等基础施工"里的用途场景因此变成独立对象,`_object_and_action` 兜底给 OPERATES,七条 公司/经营 记录由此产生。原料与套保绑定检查的是整段 compact 里"声明短语"与"商品名"各自出现,两句各出现一半也会命中,且不区分否定与计划语态。分部记录的主体绑定并读了整段 bounded quote,引文里的集团叙事会把本表为母公司口径的表格升格为集团主体。

## Goals / Non-Goals

**Goals:**

- 用途枚举截断:捕获组在"用于"处截断,只保留产品名;七条伪经营动作消失。
- 原料、套保绑定同句化:名与声明短语同句,套保句须肯定语态(开展/从事且无 未/拟/计划 前缀);钢材双角色、空数量、pending/mapped 现状保持。
- 收入口径否定边界:第三方、代收、拟/计划 收取不入公司收入;真实正例不变。
- 表格主体窄化:本表摘要注意到 母公司 等窄主体措辞时,不并读整段引文,主体回到局部判断。
- v12 隔离重跑与逐条主体/动作/对象复核。

**Non-Goals:**

- 不回写 v11 的 36/36、74/74、true。
- 不放宽门槛:双 100%、关键数字错误 0、50000 token、整轮 300 秒。
- 不授权生产,不声明规模质量;未通过不评审未见样本卡。

## Decisions

1. 新标记是 `revenue_sentence_repair=v12`,累积 v11 全部修复。
2. 用途截断在 `_activity_object_clauses` 内做:捕获组含"用于"时只保留其前文本;截断不影响既有业务句(研发、制造、销售链)。
3. 绑定同句化:以声明短语所在句(按 。 切分)为作用域核对商品名;套保句要求肯定动词存在且无 未/拟/计划 前缀;原料句要求 公司生产所需 措辞与钢材同句。
4. 收入口径:`_REVENUE_BLOCK_PATTERN` 增加 第三方/代收,`_REVENUE_NEGATION_PREFIX` 增加 拟/计划;通行服务句本身含 第三方/代收 时不作为收入与产品来源。
5. 主体并读条件:分部 span 的摘要注意到 母公司 等窄主体措辞时,主体提取只读本表摘要,不并读 bounded quote;其余行为不变。

## Risks / Trade-offs

- [截断误伤含"用于"的正句] → 截断只丢弃用于之后的枚举,动词链(研发/制造/销售)在截断前已完整保留;既有回归覆盖。
- [同句化漏掉跨行声明] → 摘要经软换行合并后再切句,真实折行不产生假句界。
- [窄主体措辞漏检] → 先覆盖 母公司 措辞,其他窄口径由后续合同按例扩展。

## Migration Plan

先做七条伪经营消失与五类反例的定向测试,再以 v12 身份隔离重跑两份冻结年报,逐条主体/动作/对象复核计分。失败不回滚 v11 快照。
