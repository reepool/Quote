## ADDED Requirements

### Requirement: Owner-closure Evidence is regenerated and validated before replay
The system MUST regenerate a new immutable Evidence plan for the frozen twenty-report cohort using the current planner and the same manifest, report identities, PDFs, and PDF-artifact hashes. Before any provider client is created, all twenty reports MUST prepare with six-core-chapter coverage and 100% Evidence traceability; the seven frozen rejected owner/substance shapes MUST NOT remain assigned as legal-empty or overview Evidence for their reviewed field; and the `920033.BJ` explicit material applicability control MUST remain owner-bound. The plan, preparation audit, and case-level correction audit MUST be content-hashed, record zero provider calls, and retain `production_authorization=not_authorized`.

#### Scenario: Every owner-closure preparation check passes
- **WHEN** the current planner rebuilds the frozen cohort from the bound PDFs and the generated scopes satisfy all case-level owner checks
- **THEN** the system freezes the new plan, complete preparation audit, and zero-provider correction audit
- **AND** the artifacts may be admitted by the one replay contract

#### Scenario: A rejected owner page recurs or a control disappears
- **WHEN** any of the seven rejected page/field assignments remains in the new plan or the `920033.BJ` owner-bound material applicability Evidence is absent
- **THEN** provider-free preparation fails with the exact case and report identity
- **AND** no provider client is created and no replacement plan is silently admitted

### Requirement: Owner-closure empirical replay is single-use and hash-bound
The system MUST admit exactly one provider-bearing owner-closure replay under a new immutable batch identity. Admission MUST bind the frozen cohort/PDFs, new Evidence plan and preparation/correction audits, archived owner-regression closure evidence, existing Gemini logical profile, extract and verify output limits, request deadline, physical provider-call ceiling, source-review rule, and readiness thresholds. The provider-bearing process MUST start through the authorized sandbox-external network path. A changed, incomplete, reused, or pre-existing input/output identity MUST fail before semantic provider execution.

#### Scenario: Frozen owner-closure replay inputs match
- **WHEN** every bound manifest, PDF, plan, audit, model, budget, and output identity matches the replay contract
- **THEN** the existing report-local service executes the twenty reports once and persists each report separately
- **AND** no historical or targeted candidate is imported

#### Scenario: A provider failure occurs after execution starts
- **WHEN** any report or scope ends with a typed transport, deadline, truncation, parse, schema, verification, or contract failure after the first provider request
- **THEN** the batch preserves the failure and continues only under existing report isolation
- **AND** no second batch, targeted rerun, model substitution, or parameter relaxation is authorized

### Requirement: Owner-closure replay results remain source-reviewed and research-only
The system MUST generate the complete frozen source-review package, review outcomes, readiness audit, and immutable comparison against the corrected external baseline. The comparison MUST report execution completion, status distribution, usable-report rate, accepted facts, Evidence traceability, provider calls and typed failures, token use, latency, sampled precision, critical errors, unresolved-review median/p90, recurrence of the seven closed defects, and readiness decision. The validation MUST close as `ready`, `hold`, or `failed` from actual results. All outputs MUST retain `production_authorization=not_authorized`; a `ready` result MAY justify only a separate restricted production-promotion change.

#### Scenario: The reviewed replay meets every scale gate
- **WHEN** execution, report usability, traceability, source-review precision, critical-error, and review-workload gates all pass
- **THEN** the audit may state that a restricted production-promotion proposal is empirically justified
- **AND** no production writer, Stage 6, scheduler/backfill, commodity exposure, value-chain publication, or DCF path is opened

#### Scenario: One or more scale gates fail
- **WHEN** the replay or completed source review misses any frozen gate
- **THEN** the change closes as `hold` or `failed` with exact source-bound findings and deltas
- **AND** it does not trigger a rerun, semantic-rule change, or production authorization
