## ADDED Requirements

### Requirement: Current segment semantics are measured by one immutable full-cohort replay

The system MUST admit exactly one provider-bearing replay of the frozen twenty-report
manufacturing/materials shadow cohort after the source-bound segment Evidence-context,
annual-duration, and unique complete-heading fixes. Before provider creation, admission
MUST bind and validate the manifest/PDF identities, corrected full Evidence plan,
provider-free preparation audit, September 11 segment-retry baseline, both external
segment validation results, current relevant implementation hashes, Gemini logical
profile, extract/verify output limits, request deadline, provider-call ceiling, source-
review rule, readiness gates, new batch identity, and output absence. The existing
report-local service MUST execute the batch and MUST NOT import candidates from any
historical, targeted, partial, or model-comparison run.

#### Scenario: Exact replay contract is admitted

- **WHEN** every frozen input, implementation proof, provider parameter, and output-
  absence condition matches the current replay contract
- **THEN** the existing report-local semantic owner may execute all twenty reports once
  under `manufacturing-materials-shadow-segment-heading-replay-gemini-20260911-a`
- **AND** each report remains a separate immutable result under the batch identity.

#### Scenario: Corrected Evidence or implementation identity drifts

- **WHEN** a manifest, PDF, corrected plan, preparation audit, repair result,
  implementation hash, route, budget, batch ID, or output path differs from the frozen
  contract
- **THEN** admission fails before provider creation with the exact drift class
- **AND** the invalid attempt does not authorize a relaxed plan or replacement replay.

#### Scenario: A report fails after semantic execution starts

- **WHEN** any report or scope ends with a typed transport, deadline, truncation, parse,
  schema, verification, Evidence, or contract failure after the first provider request
- **THEN** the batch preserves that report-local failure and continues only under the
  existing isolation policy
- **AND** no targeted rerun, second batch, model substitution, or candidate splice is
  permitted inside this change.

### Requirement: Current replay readiness is source-reviewed and research-only

The system MUST generate a complete source-bound review package, reviewed outcomes,
readiness audit, segment-recurrence audit, and immutable comparison against the
September 11 segment-retry baseline. The artifacts MUST report execution completion,
report usability distribution, accepted facts, Evidence traceability, provider calls
and typed failures, input/output tokens, latency, unresolved-review median/p90, sampled
precision, critical semantic errors, segment failure recurrence, and the exact readiness
decision. Every artifact MUST retain `production_authorization=not_authorized`; a
`ready` result MAY justify only a later restricted production-promotion proposal and
MUST NOT write approved data or enable Stage 6 or another production consumer.

#### Scenario: Complete reviewed replay meets every gate

- **WHEN** execution completion is at least 95%, at least 90% of reports are usable or
  usable-with-caveats, Evidence traceability is 100%, source review is complete with
  sampled precision at least 99% and zero critical semantic errors, and unresolved-
  review median/p90 are no greater than two/five
- **THEN** the audit records `ready` and may recommend a separate restricted promotion
  proposal
- **AND** the current batch remains research-only and production unauthorized.

#### Scenario: One or more empirical gates fail

- **WHEN** the replay or reviewed result misses any frozen empirical gate
- **THEN** the change closes as `hold` or `failed` with the exact metrics and source-
  bound findings
- **AND** it does not trigger a rerun, rule relaxation, production write, or Stage 6
  activation.
