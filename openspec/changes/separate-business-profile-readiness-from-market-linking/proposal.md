## Why

公司业务画像的当前 `status` 被商品行情映射结果驱动，导致没有可靠期货、现货或价差序列的真实产品被错误地标记为 `not_ready`。产品语义、供应链关系和价值链角色即使已经完成审核，也因此无法作为独立研究结果使用；同时，直接把实物产品等同于标准交割品或仓单会制造错误的价格暴露结论。

## What Changes

- 将公司画像完成状态与商品行情映射状态拆分。
- `profile_status` 只反映证据、语义事实、供应链关系和价值链角色是否已达到可查询状态。
- `market_link_status` 单独反映商品暴露是否有直接行情链接、研究代理链接、部分链接或未链接。
- 保留没有可靠行情链接的已批准商品暴露，不因缺少行情序列而阻塞画像发布。
- 明确区分实物产品、原料、库存、仓单/抵押品、金融套保和行情代理的语义关系。
- 保持现有商品暴露事实、历史接口和已批准数据兼容；不自动把同名产品认定为同一价格风险。

## Capabilities

### New Capabilities

- `business-profile-readiness`: 提供独立的画像状态、行情链接状态及其缺口解释。

### Modified Capabilities

无。当前没有已发布的公司画像规格文件，新增能力规格作为 API 和读取模型的权威契约。

## Impact

- 影响 `research/business_profile_governance.py` 的画像状态计算和 readiness 投影。
- 影响公司业务画像与商品暴露 API 的响应字段及状态语义。
- 需要为 `601088.SH` 等已有已批准事实但未完成行情链接的公司补充回归验证。
- 不修改年报资产管理模块、LLM 抽取流程、商品语义事实表或现有行情数据表。
