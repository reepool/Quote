## Context

用户要求数千家公司自动年报解读，明确允许次要遗漏和有据不确定性。旧v61及S1路径可以在provider=None时交付，runtime按已有field消除unresolved，正文覆盖受正则控制；大量历史逐样本修复不能证明未见泛化。已有PDF、gateway、任务持久化和事实/读取模型值得复用。既有S1修复及S2源准备脏文件必须保留。

## Goals / Non-Goals

**Goals:** 同一owner交付三类相连产品；真实模型阅读、源先行漏项检查、可靠数值与硬约束分工；有限容错；4/12/20/100至全市场的有界计划；移除误导性有效指令并清理被替代代码。

**Non-Goals:** A审核规划，B按§40实现v7全文核心读源及公司交付；旧23入口及失败保留。替换传输只证明协议，不是业务验收。不在B1建设通用跨入口语义续跑，无其他公司授权，无新网关/agent/数据库/writer/预算平台，不改用户池或生产。

## Decisions

1. 沿`company_profile_common_core`和operations/runtime/workflow/provider/read owner接续。单纯传入provider仍会被field已存在短路，故必须同步调整语义执行条件、selector可见范围和projection完整性，先1家闭环再扩4家，不先全仓拆分。
2. 当前v7替代导航门控：全部可读原文分片源先行阅读，只收集核心业务条件及证据→跨章公司合成→有限支持/覆盖核验并持久交付→一次必要补源/纠正或限用。程序打包范围，LLM判断语义相关性；不逐行抽全附注，不逐片成稿核验。条件发现独立于候选，已承担报告级漏项阅读，不重复全文清单；已发范围不等于语义召回。主要条件/三视图底线不降，同源证据按位置/ID复用，不按视图重复核；局部失败只影响有关依赖，不输入A答案。
3. 程序只对可靠结构化数值和身份/单位/锚点/预算等硬约束作确定判定。LLM识别开放语义、生成证据内摘要与角色解释；原名原数值独立保存。摘要不以逐字复制为前提，但每项重要主张有源支持。引文按产品§9.2允许有位置映射的排版空白定位并回填精确原文，非空白字符不变；定位和语义支持分开核，所属段落/标题随核验传入，单对象错误局部隔离。
4. 沿既有extract/verify协议接续：独立无候选源发现→携带实际已核交付及相关事实的主要条件覆盖对照→具体补读或限用。condition pass须绑定真实覆盖对象；程序核引用/状态，LLM判断覆盖，同维度存在或源条件本身正确不够。verify不改候选，修正形成新候选并重新核验；A独立核源。
5. 新报告核心语义必须真实模型调用；无provider不得规则降级成“可用”。相同源和语义版本缓存可复用，首发评测禁语义复用。记录真实物理调用、失败和usage；不以token>0本身作为质量证明。
6. 产品暴露不限商品：输出产品/服务收入端、重要投入成本端；角色限有证据的生产/贸易/服务及上下游类型。沿现有对象和版本化投影，不建平行图谱。已知错误屏蔽对应对象和依赖答案，无法补救给出限制，不停无关公司。
7. 验收门槛唯一引用`docs/development/company_profile_acceptance_program.md`v2；开发样本与盲测分开，先后顺序和任务卡引用`company_profile_delivery_plan.md`。保留旧首发成绩，冻结实现、模型、提示词、源和成本后才能跑盲测。
8. 所有阅读策略在同一实际发送接点检查已用/unknown、必要末端及卡内恢复，不能仅partial分支留额。逻辑请求关系覆盖跨源、同源及schema repair，不以供应商attempt或随机request_id重置恢复。成功阶段沿原checkpoint保存，已核主张及时经原owner可查，后续失败不抹去；必要补读尚未处理则核心限用。开发导航接续须A明确批准和身份校验，不作为新首发语义成功。
9. 支持性/依赖与覆盖可在有限核验请求中分别返回；先更新可信对象，再接受绑定这些对象的覆盖。源审不带候选且能发现候选外主业；同页不同段和续页均保留。核验成功一组即写入原owner，后组失败不抹掉独立可靠结果。已完成源范围不反复清点，但新增必要上下文/冲突须定向处理。
10. §40新首发不接旧导航/业务语义，只复用解析/布局/可靠原生事实；后继改码重冻、重新真实读源并分列，不拼版。冻结算法按完整客户端payload动态打包，同时核字节/输出/预留及真实末端，过大重包、真正总限停。公司合成使用跨章证据，不能逐包答案拼接或只留第一包；局部ID不丢业务。卡内300秒逻辑/150秒物理显式隔离公共默认，新身份不能由旧授权获取；研发额不证明常规/规模达标。

## Risks / Trade-offs

- 全文分片输入仍会语义漏项/幻觉 → 候选外源条件、可靠收入构成对照、必要上下文/续页补源、实际主张支持检查及A源核；已知错误退出可靠消费。20/100家实测，不承诺100%。
- 模型校验自证或正则重新变成语义裁判 → A核源、检查候选外遗漏和真实provider路径；确定性guard只挡硬错误。
- 全文阅读增加资源 → 当前协议208页源发现静态669036预留，非实际token/费用。§40明确研发上限，4家后据实测校准常规吞吐/成本；不以旧120000截掉主要来源，也不宣称研发放大即可数千家经济运行。
- 旧代码清理误删有效表格处理/既有改动 → 卡2核调用依赖和直接回归，迁移后删，源资产和冻结材料不删。
- 验收精度与工程工作量冲突 → 只核主要业务和高风险事实，补充对象有界抽样，首发与补救分列；样本外质量明确未知。
