## Context

用户要求数千家公司自动年报解读，明确允许次要遗漏和有据不确定性。旧v61及S1路径可以在provider=None时交付，runtime按已有field消除unresolved，正文覆盖受正则控制；大量历史逐样本修复不能证明未见泛化。已有PDF、gateway、任务持久化和事实/读取模型值得复用。既有S1修复及S2源准备脏文件必须保留。

## Goals / Non-Goals

**Goals:** 同一owner交付三类相连产品；真实模型阅读、源先行漏项检查、可靠数值与硬约束分工；有限容错；4/12/20/100至全市场的有界计划；移除误导性有效指令并清理被替代代码。

**Non-Goals:** 本轮不实现业务、不调用模型、不扩批、不清库。实施不建设通用agent框架、完整产业知识图谱、全行业包、价格/利润敏感性或新writer。

## Decisions

1. 沿`company_profile_common_core`和operations/runtime/workflow/provider/read owner接续。单纯传入provider仍会被field已存在短路，故必须同步调整语义执行条件、selector可见范围和projection完整性，先1家闭环再扩4家，不先全仓拆分。
2. 全报告导航＋LLM选择核心完整上下文，独立上下文源先行查漏并有界补读，再合成/核验三视图。纯关键词白名单会遗漏新披露，全PDF一次prompt或强制逐字发送全部未选附注则不能支撑规模运行；均不作为默认策略。按产品契约v3分开导航覆盖、全文已读、核心可用，未读补充附注明确显示，已知主要业务漏项仍否决核心完整。页覆盖记录沿现有元数据，不建平台，不输入A的标准答案指导选页，不追溯改变旧五次合同。
3. 程序只对可靠结构化数值和身份/单位/锚点/预算等硬约束作确定判定。LLM识别开放语义、生成证据内摘要与角色解释；原名原数值独立保存。摘要不以逐字复制为前提，但每项重要主张有源支持。
4. 在extract/verify既有provider协议中版本化全文地图、源先行清单及语义摘要/覆盖。先源后候选的独立上下文用于查漏；后续verify不修改候选，补救通过显式repair/新候选。相同模型两次调用不是独立真值，A仍按源抽审。
5. 新报告核心语义必须真实模型调用；无provider不得规则降级成“可用”。相同源和语义版本缓存可复用，首发评测禁语义复用。记录真实物理调用、失败和usage；不以token>0本身作为质量证明。
6. 产品暴露不限商品：输出产品/服务收入端、重要投入成本端；角色限有证据的生产/贸易/服务及上下游类型。沿现有对象和版本化投影，不建平行图谱。已知错误屏蔽对应对象和依赖答案，无法补救给出限制，不停无关公司。
7. 验收门槛唯一引用`docs/development/company_profile_acceptance_program.md`v2；开发样本与盲测分开，先后顺序和任务卡引用`company_profile_delivery_plan.md`。保留旧首发成绩，冻结实现、模型、提示词、源和成本后才能跑盲测。
8. 所有阅读策略在同一实际发送接点检查已用/unknown、必要末端及卡内恢复，不能仅partial分支留额。逻辑请求关系覆盖跨源、同源及schema repair，不以供应商attempt或随机request_id重置恢复。成功阶段沿原checkpoint保存，已核主张及时经原owner可查，后续失败不抹去；必要补读尚未处理则核心限用。开发导航接续须A明确批准和身份校验，不作为新首发语义成功。

## Risks / Trade-offs

- LLM导航和阅读仍会漏项/幻觉 → 独立上下文源先行主要板块检查、可靠收入构成对照、必要补读、证据约束和独立人工样本复核；明示未读范围，由20/100家实测暴露风险，不承诺100%。
- 模型校验自证或正则重新变成语义裁判 → A核源、检查候选外遗漏和真实provider路径；确定性guard只挡硬错误。
- 120000token/16请求/900秒可能不足某些报告 → 先4家实测，局部补源一次，预算耗尽限用；不得裁掉主要板块后声称通过。预算调整需前置裁决。
- 旧代码清理误删有效表格处理/既有改动 → 卡2核调用依赖和直接回归，迁移后删，源资产和冻结材料不删。
- 验收精度与工程工作量冲突 → 只核主要业务和高风险事实，补充对象有界抽样，首发与补救分列；样本外质量明确未知。

## Migration Plan

本轮更新需求、计划、流程、索引与旧规范适用范围；新delta为目标，未声明实现。卡1选显式新政策身份实现，旧输出保持可读；卡2完成替代并清理已无人调用的规则/版本开关/临时runner，未完成不能宣称迁移完毕。通过S2/S3后按S4明确发布边界。切换失败停止新写入，保留可靠已有记录，不回启旧错误生产链。所有删除在清单中记录依赖、替代和Git恢复位置。
