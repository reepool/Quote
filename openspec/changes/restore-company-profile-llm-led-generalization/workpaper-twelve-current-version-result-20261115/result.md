# 6.CO：十二家同版完整真实验证结论

本组十二家各一次全新原TaskService入口已全部结束。十一家交出有源画像并在同一入口内真实执行初核、一次合并修订及最终再核；海泰停在正文前的本地章节边界定位。没有跨窗口接续、旧语义输入、边跑边改、追加尝试或第十三家。

[先看十一份新画像和缺口](profiles.md) · [同源结构索引](index.json) · [独立内容对照与禁用项](independent-audit.json) · [实际资源与验证](validation.json)。旧CN跨版本预览保留，不拼成本组结果。原始query、模型响应及旧失败不追改。

## 真实业务进展

- 八要素正文330条事实、583个指标；含可选供应链共365个事实对象、596个指标。数量不是准确率。十一家都有可选供应链信息，取得的粒度到公司位置、投入类别和客户/用途即可。
- 两家模型复核状态为completed，九家completed_with_open_findings；后者仍有未决、拒绝修订或未补遗漏，不等于失败无稿，也不等于全部准确。
- 六十项初核发现最终有42项纠正/补充获真实最终接受、2项保持隔离；另12修订拒绝、2遗漏候选、2范围未决。一个事实可能承载多条意见，42不是42个唯一新增事实。
- 青山保留公司收入2,418,990,221.17元与主营表合计2,332,376,693.65元的区别，补回浆/纸制品行业金额与内部抵销。上汽保留营业总收入、营业收入和业务构成不同科目。林海和开创同入口完成本轮全部模型问题处置。浦发已有四类业务与集团/母公司余额、营业收入/业务总收入区别，但净收入三项金额仍漏。
- 十二家公司query/export/新实例读回profiles一致；十一份有稿的原页证据坐标核对通过。旧core_complete/正式可信标志没有因模型复核自行晋升。

## 本轮发现的真正缺口

1. 海泰没有画像：选章成功后本地报`layout section boundary cannot be located: section-0063:20`。仅1次请求/19,410账本，正文和复核未发送。它是读源边界故障，不是网络、额度或LLM无法理解业务。
2. 部分正确主干仍会随复合事实撤回而损失。美尔雅收入和亏损被同一条比例口径争议连带撤回；同方抵销句拒绝后没有保留该组核心数字；浦发只有净收入比例、缺三项净额。不能靠同字段存在或别条答案把这些缺口算满。
3. 美尔雅`sm-02`将医疗本期收入空栏写成“无收入”，程序和模型复核均漏过。独立审核禁用整条事实，本组研究对照页/索引不采用，保留原query作审核原件。成本表的0.00、同比-100%均不能替代收入列的明示零。错误可局部隔离，其他公司与独立内容按原批准继续，不伪称自动路径已干净通过。

对原133项核心条件作实际交付内容对照：111项有相应内容、8项部分、13项缺失、1项不安全。其中海泰占10项缺失；这些是内容参考对照，不是正式独立准确率或召回率。部分条件含多子句，不给半项凑分。四份先完成稿做了较多独立源对象核对，余稿主要完成内容/引用身份对照；每家20补充唯一对象和全部疑点、六类正式负例没有全组做完，明确未评估，不造正式质量通过。有限核查方法与范围逐家写在independent-audit.json。

## 资源与效率

57次物理请求：官方DeepSeek35、Scorpio/Grok22；只有广州发展抽取发生1次schema恢复。57次finish均为stop，无输出截断或网络超时。失败那份模型正文已保留；只记录模型content字符串，不称HTTP原始字节。

账本1,519,919，全部按有效供应商usage结算；费用unknown，不作0元或人民币总额保证。供应商total包含未在可见input/output里完全展开的用量时按原total入账，不自行改为两者相加。

整组业务墙钟2,007.124秒，监督墙钟2,054.452秒。有稿公司业务422.794–832.185秒，中位546.425秒；各家准备26.895–40.850秒另记。全组同版冻结hash未变，每家及整组开发硬限均未触发。六家账本超过原常规120,000，费用未知，因此不是常规资源验收通过。

## 结论与后续取舍

这次已证明当前版本可连续产出多行业有源画像和有实际作用的复核纠错，不再只是受控夹具或跨版旧稿。但未达到正式全组通过，S1仍0/12、生产not_authorized。

下一步先做一个零新模型的合并共性修正窗口：用本组保存的真实选章/响应，解决章节边界导致无稿、核心复合事实连带丢失及空栏被肯定化这三类现实问题；只复验变动和直接回归，不追满供应链、所有同比或次要子公司明细，不新建审核/预算/抽取平台。修正后再统一裁定正式质量与必要的同版验证范围，不自动重抽十二家或逐公司开补句窗口。新的真实调用须另获限定授权。

本轮未修改业务代码/共享配置，复用既有108+6直接验证和原TaskService证明；运行及离线快照/引用/版本/资源核对是本次验证，未新跑pytest。OpenSpec严格校验及最终清理见validation.json/cleanup.json。有限Review发现A类sm-02可靠展示错误已在派生研究交付禁用；自动链上的根因仍未修复，不能宣称无已知生产缺陷。B类细分产品、供应链、额外数值收集后置，C类原配置/骨架/退市/FX等既有与并行改动不动不纳。

本轮清理39,514,748字节：worker finally移除运行根22,930,683字节，收尾移除准备副本/过程日志/四个脚本/编译缓存和重复导出JSON共16,584,065字节。被删内容可由保留的正式源、原查询及权威快照重建；原模型响应、必要查询/人读证据、正式PDF/有效缓存/十二尝试标记和他人文件不删。导出JSON与query内profile逐对象相同才移除，hash留cleanup.json，不保两份权威事实全文。
