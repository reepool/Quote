## 内容合同：按八项认识一门生意，不以八项齐全挡展示

抬头注明公司/证券、报告期、报告版本和集团/母公司口径；已有控股性质、主要经营主体可顺带展示，不建工商采集新链。正文采用“业务总览＋板块结构表＋经营/上下游说明＋近况与缺项”，不按技术状态组织全文。篇幅以讲清业务为准，约800—1500字可作参考，不以字数验收、不为凑字重复。

| 要素 | 本次应主动查找和写出的内容 | 优先查找的章节族（仅起点，实测后校正） |
| --- | --- | --- |
| 业务结构 | 主业、重要板块及其主次；区分母/子公司、配套环节和独立销售业务，无权重依据不猜排序 | 主要业务、经营模式、管理层讨论与分析、分部信息 |
| 产品/服务及用途 | 重要产品/服务原名，分别用于什么或服务谁；不是只有名词清单 | 产品与用途、业务介绍、分板块经营情况 |
| 怎么赚钱 | 自制销售、贸易、加工、服务收费或资产运营等具体机制；金融按报告讲利息/手续费等来源 | 经营模式、经营分析、收入构成、分部与收入相关附注 |
| 规模与业务权重 | 可靠公司收入总额、主要分项/占比或其他适用规模；区分主体、期间、单位、小计和总额 | 主要会计数据、合并利润表、营业收入/分部/主营构成表 |
| 经营方式与关键投入 | 自产/外包/运营方式、主要投入或资源、自己掌握的环节；金融不编木材式原材料 | 采购/生产/经营模式、成本分析；金融的资金来源或经营资源披露 |
| 客户、渠道与市场 | 客户类型/应用行业、直销经销/服务渠道、地区市场；用途不等于具名客户关系 | 销售模式、客户与地区分析、业务经营情况 |
| 关键经营影响因素 | 报告明确说明的需求、原料、产品结构、监管等影响，不猜传导率/利润弹性 | 经营讨论、成本/毛利变化原因、风险因素、行业情况 |
| 最近的重要变化 | 主业/产品结构/业务布局的重要已发生变化，或有据地说明未重大变化；计划单列 | 报告期经营情况、主营变化、重大事项、未来展望（只标计划） |

前六项构成实用画像主体，后两项按重要披露补充；这不是新增生产必填schema或八项全pass门禁。每项有实质内容或有据缺项说明，不用同一句主营填多个栏。产品与下游、渠道与变现机制可以合并叙述但关系须清楚。已知错数/错主体不可靠发布；未核内容仍待核。规模优先复用同报告/期间/主体的可靠正式财务事实，不新建财报抽取；引用须能追到相应表头、单位和数值。原报告未披露的金额/比例/客户名不得补造。

## B连续实施：先产出，再拿原文查遗漏

1. **先清后做/直接链短检。** 记录Git与尝试占用基线，盘点清本人已结束无依赖过程物。只检查原TaskService→公共网关→样稿成稿/原writer→query/export这一条链，局部调整八要素提问、相关章节上下文、任务输出容量和Markdown呈现；不先做全报告Gold、章节研究报告或完整三视图mock。
2. **两家各一次生成。** 在本次源选择/成稿提示中提出上述问题，优先读能共同回答多项的相关章节与必要表头续页，再跨章成稿并立即保存。导航/读源不能耗尽所有次数而不给成稿机会。有余量且发现具体缺项时可在同一入口内定向补读/合并，全部计原6物理/1恢复/60000/600秒；不按八项各开一轮、不重发成功源、不为一条反复补齐。每家生成即保存，不能让一家缺项阻塞另一家。
3. **运行后离线对照。** 冻结本次模型正文后，用现有正式目录/解析对八项做一次有界人工复查：从上述相关章节及必要续页找可支持的漏项，而非全文逐句审计。青山用本轮既有样稿和同一正式解析作同样对照，不调用模型补写/覆盖首次query。人工发现必须单列“B原文复查发现”，不能混进原模型产出或称为A独立审核；未定位到的如实未定位，不假定未披露。
4. **归纳真正的难点。** 对观察到的缺口区分：源未定位/未读、源已发但源审漏掉、源条件已有但成稿漏写、引用/表头或口径失败、预算/请求槽停止，以及已核范围确实未披露。不足以定位链路时写未知，不凭模型说没找到就判未披露，不把技术问题统称模型能力。对能核实的遗漏列原页短引文及实际到达阶段即可，不新建追踪平台。
5. **同窗交业务结果。** 正文、对照和难度结论一次交接；卡内P0—P3局部修补、直接回归、Review/Git和收尾由B自主连续完成，不逐字段等A批准。本卡没有新的付费观察授权，已用入口不恢复；两家冻结发送后不热改再补跑。
