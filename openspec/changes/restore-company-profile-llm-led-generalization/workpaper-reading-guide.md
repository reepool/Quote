# 公司画像阅读与返回结构指引 v1

依据上汽、浦发和青山的实际读源经验（2026-11-12）。这是初步章节族指引，不是固定章号、页码或公司规则；后续以新报告实际遗漏收敛。

| 画像问题 | 优先查找的章节功能 | 需要返回的实质内容 |
| --- | --- | --- |
| 做什么 | 主要业务、经营模式、业务回顾 | 主业与重要板块，制造/贸易/运营/服务的区别 |
| 卖什么、给谁用 | 产品/服务及用途、各业务板块经营情况 | 产品服务原名、用途、客户领域；没有用途不按常识补 |
| 怎么赚钱、规模权重 | 主营业务分析、收入成本、业务板块、主要财务指标 | 公司收入、主要板块收入/占比或适用运营规模，优先于注册/荣誉/系统细节 |
| 怎么经营 | 经营模式、采购/生产/销售、业务模式 | 自产/外购/贸易/服务、运营资源；银行按资金和服务表达 |
| 客户/渠道/市场 | 业务回顾、产品应用、市场/销售渠道 | 客户类别、行业领域、渠道与地区，不把用途当实名交易 |
| 经营因素/变化 | 管理层讨论、主要风险、业务变化/展望 | 本期变化与因素，计划与已实现分开 |
| 供应链（可选） | 以上章节里的原料采购、经营模式、下游用途 | 公司位置、主要投入、下游客户领域；未找到只说明缺项 |
| 必要补充 | 分部信息、收入确认、必要关联购销 | 只补会改变主业理解或数字口径的缺口，不默认读全部附注 |

先阅读该报告目录/标题树，选择完整子节；同一处能提供多项信息时优先集中到它。表格保留表头、币种单位、本期上期和跨页语境。荣誉、治理、细碎注册及技术参数后置。

返回仍为 `company_profile_workpaper.v1` 的同源JSON投影：原八项 `elements` 不变；可选 `supply_chain` 包含 `position`、`upstream_inputs`、`downstream_customers`。三个可选元素继续使用 `{status, facts, limitations}`，每个事实复用 `{fact_id, text, subject_scope, period, evidence_ids, metrics}`。证据必须来自本请求章节包，数值保留原指标/单位/期间；未选未读不是未披露。

供应链可为null或具体缺项；缺失不阻止已有画像保存、查询和导出，也不触发额外付费补齐。已知错数/未知引用仍要隔离，不以“可选”免除正确性要求。旧底稿无supply_chain时原样可读。

本轮三份报告的增量经验：主营业务/经营模式子节最适合获取实际角色、投入和客户用途；行业趋势/未来战略不能单独证明已发生采购或已有能力。青山风险段的“废纸为行业原料”不等于公司已采购废纸，“企业+基地+农户”战略目标不等于本期已经形成该模式。能源合同同时保留实际履行与未来起供/FID状态。服务企业可交人员、场地、运输等资源与游客场景，不强找原材料清单。详见本轮审核交接。
