# 公司画像阅读与返回结构指引 v1

依据上汽、浦发和青山的实际读源经验（2026-11-12）。这是初步章节族指引，不是固定章号、页码或公司规则；后续以新报告实际遗漏收敛。

| 画像问题 | 优先查找的章节功能 | 需要返回的实质内容 |
| --- | --- | --- |
| 做什么 | 主要业务、经营模式、业务回顾 | 主业与重要板块，制造/贸易/运营/服务的区别 |
| 卖什么、给谁用 | 产品/服务及用途、各业务板块经营情况 | 产品服务原名、用途、客户领域；没有用途不按常识补 |
| 怎么赚钱、规模权重 | 主营业务分析、收入成本、业务板块、主要财务指标 | 公司收入、主要板块收入/占比或适用运营规模，优先于注册/荣誉/系统细节 |
| 怎么经营 | 经营模式、采购/生产/销售、业务模式 | 自产/外购/贸易/服务、运营资源；银行按资金和服务表达 |
| 客户/渠道/市场 | 业务回顾、产品应用、市场/销售渠道 | 客户类别、行业领域、渠道与地区，不把用途当实名交易 |
| 经营因素/变化 | 管理层讨论、主要风险、业务变化/展望 | 本期变化与因素，计划与已实现分开 |
| 供应链（可选） | 以上章节里的原料采购、经营模式、下游用途 | 公司位置、主要投入、下游客户领域；未找到只说明缺项 |
| 必要补充 | 分部信息、收入确认、必要关联购销 | 只补会改变主业理解或数字口径的缺口，不默认读全部附注 |

先阅读该报告目录/标题树，选择完整子节；同一处能提供多项信息时优先集中到它。表格保留表头、币种单位、本期上期和跨页语境。荣誉、治理、细碎注册及技术参数后置。

返回仍为 `company_profile_workpaper.v1` 的同源JSON投影：原八项 `elements` 不变；可选 `supply_chain` 包含 `position`、`upstream_inputs`、`downstream_customers`。三个可选元素继续使用 `{status, facts, limitations}`，每个事实复用 `{fact_id, text, subject_scope, period, evidence_ids, metrics}`。新增可选 `generation` 由本地成功网关回执生成，不由模型返回：分别展示 `select_profile_sections` 和 `extract_profile_workpaper` 的实际模型、来源、请求/响应身份、usage与版本；正文阶段附真实section IDs及物理页。供应商换源后归因于最终成功响应，失败尝试不记作作者。旧workpaper无该字段继续可读、显示未知。

证据必须来自本请求章节包，数值保留原指标/单位/期间；未选未读不是未披露。供应链可为null或具体缺项；缺失不阻止已有画像保存、查询和导出，也不触发额外付费补齐。已知错数/未知引用仍要隔离，不以“可选”免除正确性要求。旧底稿无supply_chain时原样可读。

读源接续v4：模板标题包含“超过50%或新增或严重依赖”等多条件时，不把其中一项套到每行；每个比例保原分母，营业利润/净利润不得串列。来源单位相互冲突须说明、优先无歧义重复出处。期间影响不等于事件发生期间；子公司注册业务/产品不等于本公司实际采购。这些都是通用语义要求，不注入目标公司答案。

后续主线：同一表同时列板块分项、小计、内部抵销与合计时，应共同保留，不能只摘总计后声称原文无调节。先把主要业务权重解释清楚，再取次要注册/荣誉细节。该项来自本轮同方实际遗漏；当前v4两份原结果不改，不声称新提示已经真实复验。

读源接续v5：分部表若明列分项小计、内部抵销和调整后合计，分别保留，不把净额伪装为分项简单相加。这是通用口径解释，不按某公司金额写答案。

2026-11-12复核闭环：低成本抽取后，由指定高思考/高能力profile拿同一原文包逐条复核并返回完整checked fact IDs。确认错误的claim先隔离；可纠正项最多一次定向修订，必须由复核profile再核并通过原文/数值硬校验后替换；失败保留旧文和限制。不自动补全所有重要数字，不为补次要字段扩读全文。reviewed不是trusted/approved，原始与修订版本都有审计轨迹。

本轮三份报告的增量经验：主营业务/经营模式子节最适合获取实际角色、投入和客户用途；行业趋势/未来战略不能单独证明已发生采购或已有能力。青山风险段的“废纸为行业原料”不等于公司已采购废纸，“企业+基地+农户”战略目标不等于本期已经形成该模式。能源合同同时保留实际履行与未来起供/FID状态。服务企业可交人员、场地、运输等资源与游客场景，不强找原材料清单。详见本轮审核交接。
