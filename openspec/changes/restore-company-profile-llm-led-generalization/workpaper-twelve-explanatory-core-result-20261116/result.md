## 为什么仍有阻塞，下一步只做什么

主要问题已不在“没有章节材料”或“尚不能写画像”，而在原消费链的三个共性断点：

1. 广州两次stop响应同为23448字符，JSON缺闭合且根层级不完整；简单离线补一个末尾对象闭合符可解析，但company_features/limitations嵌在elements内，不能直接认定合同合格。相同重发未解决结构问题，原失败保持。仅诊断索引见[format-diagnostic.json](format-diagnostic.json)，没有执行/采纳恢复候选。
2. 上汽初核列39个ID不精确覆盖已知事实，海泰初核的omission形态指向现有事实；现消费将整组复核意见拒绝，合法部分也未进入后续闭环。应保合法局部处理、未核/坏项仍incomplete，而不是追求形式全绿。
3. 上汽等有正确原文金额和结构化值，但正文换算/舍入表达不满足字面定位，整个复合事实被剔除，连主要收入构成一起丢失。应在不猜单位/科目、不放宽主体/期间和来源底线下，保原文及局部限用，不再以加长提示词或整批重抽解决。

下一仅建议一张合并零调用消费修正卡，复用本次原始响应验证上述三个现实断点；不另建框架、换路由、增加画像字段、追供应链精度或继续十二家付费重跑。通过后才考虑最短必要复核接续的新有界授权，不借本卡余额。修结构不等于自动语义通过，源核发现的问题继续局部处理。
