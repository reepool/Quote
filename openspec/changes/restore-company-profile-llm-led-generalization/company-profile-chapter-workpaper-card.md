# A/B任务卡：人工有源底稿→集中章节文本→同结构抽取

> 2026-11-11，v9，依据[规范对齐§257](review-submission.md#257-v9文档对齐人工底稿章节文本同结构抽取)。遵循[产品目标](../../../docs/development/company_profile_product_and_industry_semantic_requirements.md)、[验收§7.109](../../../docs/development/company_profile_acceptance_program.md)、[交付路径](../../../docs/development/company_profile_delivery_plan.md)、[A/B v3](../../../docs/development/ab_role_development_workflow.md)。沿唯一现有change，不另起平台。本轮仅文档同步，下列是后续实施顺序；不是代码已实现或新的真实调用批准。

## 唯一目标与下一业务交付

A先直接阅读上汽集团已有正式2025年报，交有实质内容的人工JSON底稿及由同一JSON形成的人读画像，并说明集中来源与实际缺项。B再以这一份参考接章节文本和同结构抽取，不能让执行链修复反过来拖住A的首份业务交付。人工参考不是旧模型答案重命名，不算模型成功或S1公司。

主动回答业务结构、产品/服务用途、赚钱方式、规模/权重、经营方式/投入、客户/渠道/市场；经营因素和重要变化按披露补充。每条事实与数字带章/节/页和原文，找不到的具体说明；不以八项全pass、全部行业指标或正式三视图可用作为基础底稿展示门槛。

当前三家尝试3/3已用：青山有模型成稿，上汽只有源审、浦发在模型前失败，原卡未交齐三份画像。原输入、回执、失败、计数保留；本卡不复活旧窗口、第4轮或迁移余额。

## 结构与来源合同

统一字段/证据以[workpaper规范](specs/company-profile-llm-led-delivery/spec.md#requirement-structured-company-workpapers-have-one-evidence-linked-contract)为准，版本company_profile_workpaper.v1；origin区分人工参考、真实模型、受控替身。JSON与人读版同源，复用现有事实/Evidence模型、单writer及query/export，不建新数据库、schema registry或八种任务。

每份报告先依据目录、书签和正文标题树确定相关子节的实际边界，页码仅作定位。优先选择主体期间正确、语境完整、能共同回答多项问题的高价值章节；同一事实无需遍读全部重复出处。主源足以解释业务即先交，只有主要业务/机制缺口、主体数字冲突或表格残缺才定向补读；次要细节可留空，不把未搜到称为全报告未披露。不按固定页号/页数、“业务介绍再加一页”或历史精确章名套新公司。

## 连续实施顺序

1. **A参考实物。** 从正式原文独立产出human_reference JSON、人读版、选定章节/必要备用来源及选择和停止理由。八个空标题、空schema或规划不能代替底稿。参考JSON只保一套，不复制整库。
2. **A/B核实际输入。** 交可供LLM阅读的所选章节包：报告版本、标题路径/真实边界、原页跨度、段落与表格；不是若干候选页的短预览。先看这些文字能否支撑画像，再判断缺口。
3. **B保真转录。** 沿共享PDF/layout/recovery owner整理章节文本，保留表名、主体、期间、单位、行列头、本期上期、空/合并单元格关系、符号和脚注。续表确认关系后才合并，各片保原坐标；不能安全恢复就标unclear或使用既有定向版面/图像能力，不猜列、不全报告OCR、不另建parser。
4. **B同结构接入。** 对齐版本化提示、schema、解析、现有TaskService/公共网关/单writer/query-export和渲染。LLM可直接由原章节包给有源JSON，程序标准化并呈现，不强制先条件清单、另成稿、逐条coverage循环才给pending答案。请求按实际载荷计量，不以假想全报告尾额挡草稿；真实单次/累计硬限继续有效。
5. **异公司真实对照（待新授权）。** 拟用浦发已有正式年报，属已知异类型样本，不称盲测。从它自己的目录选章节，使用同一结构；可给通用标准和异公司的格式例，不能给待测公司人工答案/旧语义。结果按实际所得/遗漏/错数和阅读成本，分析章节选择、转录、模型语义或消费的难点，再决定最小下一步。

## 自主范围、验收与停止

后续收到开发指令后，B在人工内容标准明确的范围内连续完成局部接入、P0—P3直接修复、相关短检/Review/Git及清理，不逐字段等A。只证明参考JSON→人读一致、实际章节/表格材料可读可定位、同结构结果能沿原owner保存读回及已发现的直接边界；不以全量mock或新门禁拖延业务底稿，受控成功不作真实模型分数。

交接依次提供：人工JSON/人读版及章/节/页；实际章节文本/表格和选择/放弃理由；B接入读回或首个具体阻塞；只有另获调用批准后才附真实抽取及资源。没有的写未交/未运行，不用文档校验或JSON键齐全冒充业务通过。所选章节覆盖不等于全报告召回，缺项可以限用交付但已知错数/错主体不得可靠显示，正式S1/S2/生产标准不追改。

当前新增代码执行、模型调用、探针、物理请求、恢复、可发送绑定及付费额度均为0。本次文档批准不启动上述动作；未来真实观察须另冻公司/来源/版本/路由/次数/usage/时间/费用unknown处理及停止条件并获批，不套用旧60000/120000余量。需要扩大内容或权限、处理无法隔离的既有改动时报告裁决，不自动新公司、补窗、模型竞赛或生产。人工参考/离线结果足够当前阶段即交，不为理论完整无限补齐。
