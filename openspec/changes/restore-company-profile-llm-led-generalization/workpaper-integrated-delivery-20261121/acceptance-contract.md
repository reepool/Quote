# 6.ET 统一研究交付验收与后续规模合同

冻结时点：真实观察启动前；A负责语义判断，B负责真实执行和证据。依据产品v9、验收计划v2 §2—6及用户本轮“一并规划一并跑”的要求。不是新的评分服务或程序语义门禁。

## 本卡立即执行的交付验收

| 方面 | 本卡检查与交付 | 不据此推断 |
| --- | --- | --- |
| 首读交付 | 实际日常job文件入口、非空有源稿、首读完成即API可读，高阶复核未完成不拖停其他首读 | 首读已准确或正式可用 |
| 基础业务 | 原文支持公司做什么、主要产品/服务、怎么取得收入；多个主要业务不能只剩一个 | 每个细项/科目/数值必填 |
| 源复核 | 实际模型/请求/状态、失败阶段、修订/终核是否实际发生，保留独立原稿和后继 | completed即全正确或无漏项 |
| 内容准确 | A核原文的主要业务/关键数字/实际修订分列；未核内容沿实际待核或模型核状态 | 未核默认正确、模型自评代独审 |
| 缺项与不确定 | API和人读版显示未获取/未核/建议、已读/未读范围；约/近/超等保原文 | 缺项就是未披露/零业务；缺补充拒整稿 |
| 一致消费 | 同报告/hash父链下API、JSON、人读版和新实例一致；隔离/替代正文不复活；同run_id不新发 | 跨轮事实已自动语义去重/一致性解决 |
| 资源 | 首读可见时间、复核时间、总墙钟、请求/恢复、已知usage与未知预留、费用状态 | 供应商未报费用等于0或符合旧900秒档 |

供应链粗粒度可选，不为补满单开阅读；company_features允许模型依已读原文自主挑选有解释价值的条目，与普通事实同样复核。小错/漏项允许被发现并按对象限用，已知错主体、错期间、错金额或无来源不能作为确定事实外放。合法不确定可以保原句，不强制转换成一个确定值。

研究版交付的结束条件为：已有可靠内容可消费、缺项/限制明确、已知影响当前结果的错误得到局部隔离或说明，日常首读/复核/按需精读可实际运行。可靠部分不等待全部可选字段，研究版成立不等于S2正式通过。

## 同卡完成的正式扩量合同与裁决

正式下一阶段必须先明确用户的新范围裁决，因为旧S2首组和唯一确认组均已失败并结束。两份已见日常观察以及保存15稿不能改称新盲测、不能与旧最好结果拼接，也不能把停止的5家“补跑”成首发完成。

若另获新正式方案授权，仍使用现有验收计划的基线，不为通过降低阈值：20份未见、四类6/6/4/4，沪深各至少6、北交至少2、至少8个申万一级行业；先按正式公开报告目录/核心章节独立冻结源参考，再一次同版首发。首发至少18/20、补救后19/20，核心宏召回95%、已审唯一对象准确率99%、已知底线零外放、查询/导出/磁盘一致及原人工补救上限。首读未交付/模型超时/源复核失败、未核对象和确有内容错误分别报告，失败/未交付仍占公司分母，不以“通道故障”从召回分母删除。

95%是按独立源条件逐公司平均的召回，不是字段非空率；99%是实际查过的唯一对象正确率，不是LLM通过率。核心三问题及全部主要板块/关键金额核原文，补充每家至少20个/不足全查、S2至少400个实际补充对象；不足如实报告，不重复计数或拿少量对照推算全组。额外补读只修该问题，不偷偷增加整个必填清单。

正式新方案通过后才准备另100家受控研究试运行，沿原30/30/20/20及交易所/行业分层、首发90/100、补救后95/100及95%/99%等要求；再通过才可按100→500→其余每波不超过500研究覆盖。每批的名单、总预算、版本、消费者、停止及生产授权在实际扩量前冻结；本卡没有默认扩20/100或生产权限。A在本卡末端必须给扩大/限范围使用/停止扩大三选一实测结论，不能只留“以后再判断”。

## 有限证据的复用

现有15稿共有433个可读记录、694指标，含跨轮相似/重复经济内容，不当作433个已去重经济事实。旧独审仅对当前事实正文/指标/来源hash相同者复用；变化对象使用后继独审或新读原文。复用的旧判定不是本次新独审，统计时按reading work ID+fact ID+内容hash定位，形式计数不代替A的语义判断。原有限审查不自动成为全报告99%或全市场准确率。

运行/开发前先盘点本人旧临时物，必要证据保一套后清库/重复导出/脚本/过程日志。原报告/有效缓存、真实研究根和首次失败/attempt保护，A/B写集分离，最终一个review交接与一次普通提交/推送。
