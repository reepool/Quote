# 6.EO：同一应用入口完成首读与后续复核

`execute_published_task`与`CompanyProfileTaskService.execute`现在支持两个明确动作。`first_read`接收股票清单，只完成原选章/抽取和待核稿交付；`review_batch`接收已保存的完整计划，复用原复核接续，不重新抽取。调用方显式提供原模型、处理身份、预算和存储，不再为两阶段分别绕过统一分发。调用示例见[接口文档](../../../../docs/api/restful_api.md)。本轮没有新增运行器、业务循环或共享CLI默认模型接线，也没有新付费调用。

首读模式进入原工作ID，已完成同身份工作重提不发送；仅处理本次入队ID，不加载全市场候选或捞旧队列。服务身份在正常结束和异常时均恢复。发布停止、有限预算、显式M4计划及绑定继续生效，活动first-expansion不能借新动作绕过。复核清单与另给股票范围须相同，源/原稿/hash检查、旧request幂等、两次同因新失败暂停及剩余计划接续均沿既有owner。旧`run/resume`仍能执行当前底稿的内联复核。
