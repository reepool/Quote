## 已确认的故障与停止

[环境判据](environment-diagnosis.json)：沙箱内api.deepseek.com和scorpio.reepool.com均gaierror -3；获准的沙箱外只读DNS均成功。四个业务进程在同一隔离网络命名空间内，观测时TCP/TCP6连接均为0，未收到模型响应。这个判据支持“执行权限环境错误”，不支持“LLM不会读年报”或“高阶模型质量差”。

发现后立即停止后续派发、SIGUSR1封四家后继发送。原600秒物理时限未能让请求返回；没有拿到足够栈证据解释内部为何未退出，不能捏造具体客户端根因。随后核准四个本人PID/命令身份并SIGTERM终止，原主管退出。没有重新开四家、继续余八家、热修源码、借余额或换模型。原预算/失败不重置。

这轮暴露的是我的启动就绪判断和环境选择失误。应纠正的是：已批准联网任务从获准的联网exec启动，在同一权限环境先做只读DNS/配置接线核对；不用新的语义补丁、换模型或扩大预算处理它。当前授权按失败结束，未完成目标不能自动续跑。
