## Context

日照真实 p9 形态:"公司的经营模式主要为:为客户提供……服务,计划收取货物堆存费……"——按逗号切分后,服务从句无计划措辞,计划性收取在下一从句;从句级守卫放行服务从句,借用后续收取动词后整句成立。v15 对同一句返回 false(v15 尚未引入 为客户提供 替代路径时的行为),v16 引入后回归。计分方面,收费机制判定 `in_source=true` 进入召回与准确率两个分母,日照 Overview 又另计 carrier 判定,同一记录双重入账。守卫条款已写入归档 delta,主规格尚无对应要求。

## Goals / Non-Goals

**Goals:**

- 计划性收取句级否决:句内任一从句出现 尚未/拟/计划/预期/将+收取/形成,整句不构成公司收入。
- 计分一一对应:收费机制判定唯一对应日照 Overview 记录并核完整正文;去掉该记录重复的 carrier 判定;准确率 28 个对象各评价一次。
- v17 隔离重跑:双 100%、关键数字错误 0、整轮≤300 秒、共享 50000 token。

**Non-Goals:**

- 不回写 v16 的 17/17、29/29、true。
- 不改计分框架,不授权生产,不声明规模质量;未通过不下发未见样本卡。

## Decisions

1. 新标记是 `revenue_sentence_repair=v17`,累积 v16 全部修复。
2. 计划守卫升为句级:句内 `(尚未|拟|计划|预期|将)[^。；;]{0,12}(收取|形成)` 命中即整句淘汰;免费措辞保持从句级(免费附带服务不否决取得货款);拒收从句与第三方句级守卫不变。
3. 复核映射:收费机制判定唯一对应日照 Overview 记录(核完整正文),日照不再单列 carrier 判定;中直 carrier 判定保留;准确率分母 28。
4. 主规格同步:在 `company-profile-a-share-delivery` 主规格追加计划性收取句级否决与计分一一对应的最终行为要求,并记录有限验收结论。

## Risks / Trade-offs

- [句级计划守卫误伤"计划中……将收取"以外的正句] → 守卫只匹配 计划词+收取/形成 的紧邻组合;既有正例回归覆盖。
- [去掉 carrier 判定后概览记录少一次核对] → 收费机制判定核同一记录的完整正文,覆盖不减少。
