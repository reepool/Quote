## Context

v17 正式轮在 600011/600028 修复样本上有限通过,边界修复(计划收取句级否决、守卫作用域、计分一一对应)已合入并同步主规格。已观察公司增至 16 家。计时口径沿用固定者:正式轮为该身份在独立目录的首次真实执行,其整轮测量即门槛值;环境重试计入并保留。

## Goals / Non-Goals

**Goals:**

- 冻结显式排除全部 16 家已观察公司。
- 计划重复读取一致,两家都是未见样本,且一服务、一制造。
- 运行、查询、导出使用完整 v17 身份和独立目录,两家进入同一观察,整轮实测含环境重试。
- 复核清单在看到交付之后从原文独立建立,口径沿用固定者:答案正文独立判断,每条交付事实唯一对应判定,重复披露不重复增加召回,跨页印刷冲突保留印刷栏目。

**Non-Goals:**

- 不改同身份默认排除。
- 不预填分数,不回写 v16 的 17/17、28/28、true 或任何历史轮次。
- 不授权生产,不声明规模质量;行业包、六章包及框架优化继续后置。
- 本轮未通过前不安排再下一组。

## Decisions

1. 已观察集合就是任务卡给定的 16 家,冻结调用传入这个集合。
2. 新目录是 `reports/m4_v17_unseen_small_batch`。处理身份是默认身份加上 `revenue_sentence_repair=v17`。
3. 运行顺序按计划中的服务公司、制造公司。查询和导出选择同一身份。
4. 复核清单从两份新年报原文独立建立,新分母不固定为 17 或 28;无商品角色的公司记为有检查范围的负例。

## Risks / Trade-offs

- [漏掉刚跑过的两家] → 排除集显式包含 `600011.SH` 和 `600028.SH`,并用重复冻结核对。
- [新年报披露形态触发新缺口] → 失败如实保留,按真实漏项另立修复卡。

## Migration Plan

先冻结并核对计划(历史文件字节不变),再运行、查询、导出,最后独立复核计分。失败不回滚已有观察。
