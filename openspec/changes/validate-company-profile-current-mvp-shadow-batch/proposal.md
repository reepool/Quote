## Why

The last complete twenty-report shadow result predates the current four-model failover,
dynamic output budgets, Evidence-routing fixes, invalid-item isolation, and segment
subject normalization, so its zero usable-report rate cannot measure the current MVP.
A single version-bound batch is now needed to decide whether the present implementation
is ready for a separate restricted production proposal without returning to per-company
retry loops.

## What Changes

- Freeze the existing twenty-report cohort, PDFs, governed Evidence inputs, current
  implementation revision, four-member `semantic_extraction` pool, dynamic token policy,
  review rule, and existing readiness thresholds as one current-MVP validation contract.
- Add one new immutable batch identity and a thin admission mode that delegates to the
  existing report-local shadow service while rejecting the obsolete Gemini-only replay,
  drifted inputs, reused outputs, and production consumers.
- Execute the cohort exactly once, preserving report-local success and typed failure;
  do not tune prompts, fields, models, token thresholds, or deadlines during the run and
  do not target-rerun or splice any report.
- Produce a source-bound blocker review, empirical readiness audit, and immutable
  comparison against the September 11 baseline, treating `usable_with_caveats` as usable
  under the current research policy while retaining substantive blockers.
- Close the validation as `ready`, `hold`, or `failed` from the frozen gates. A `ready`
  result may justify only a separate restricted production-promotion change.
