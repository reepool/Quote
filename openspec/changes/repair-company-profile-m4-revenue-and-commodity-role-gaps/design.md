## Context

归档观察使用 `owned_page_facts=v8` 和 `material_input_facts=v1`，公司是 `600007.SH` 与 `600010.SH`，cutoff 是 `2026-09-17`。独立复核是 recall 5/9、accuracy 5/5、critical numeric errors 0。准确率只覆盖命中的五项。

收入遗漏出在 `_overview_source_text`：它保留首句主营说明后立即返回，同段的“营业收入主要来源于……”被丢掉。商品遗漏发生在进入接受链之前。采购和能源费用没有被选为证据，“生产与销售”只留下了生产动作，所以现有 Activity、Relationship 和商品投影没有可投影的事实。

`load_m4_next_batch_plan` 只接受 `reports/m4_next_small_batch/` 下的唯一计划。直接换 identity 再跑会写回这一个目录。

## Goals / Non-Goals

**Goals:**

- 同一有界证据中的明确收入句进入现有接受、持久化、查询和导出。
- 公司主体明确的销售、采购和能源披露进入现有商品角色，并带期间和来源。
- 修复观察使用新的 processing identity 和单独的快照目录。
- 用这两份冻结年报做定向测试、受控交付和独立重读。新分数由阅读计算。

**Non-Goals:**

- 不改写原 5/9、历史 8/9 或 9/9，不改旧导出字节。
- 不把否定句或第三方收入补成公司回答。
- 不把 `7,407,073` 元拆成各能源金额或实物耗量。
- 不新增样本、行业包、六章包或第二套执行链。
- 不授权生产，不声明规模质量。

## Decisions

1. 收入句留在同一段有界证据里。投影在找到主营句之后继续收集同段明确收入句，而不是在首句后返回。否定句和没有公司主体的第三方收入不进入收入维度。
2. 商品选择补在接受之前。公司主体的销售、采购和能源披露成为现有 Activity 或 Relationship，再走现有商品投影。销售和采购是两个方向。目录里没有的名称交付为 pending，不丢弃。
3. 逐名清单固定为：600007.SH 的蒸汽、热水、电；600010.SH 的钢铁、稀土精矿、萤石、焦化产品销售，以及铁矿石、白灰、石灰石、进口矿、焦炭采购。蒸汽、热水、电共用 `7,407,073` 元这一笔合并费用。
4. 修复 identity 在现有 v8 与 `material_input_facts=v1` 上增加一个修复标记，只由这次 owner 调用传入。`default_processing_identity()` 不变。
5. owner 显式接收修复计划路径和快照目录。旧的唯一计划读取继续只服务 `reports/m4_next_small_batch/`。修复快照写到单独目录，计划、live-run 和 source-review 都在那里。
6. 仍使用冻结的两份年报和 cutoff `2026-09-17`。先跑业务边界测试，再受控运行、查询、导出，最后独立重读。三个商品披露组在复核时展开成逐名清单。新分数不预填。

## Risks / Trade-offs

- [同段收入句被第三方或否定句污染] → 只接受公司主体的肯定收入句。
- [把合并电费拆成三种能源的数量] → 金额保持一笔，角色按名称分别保留。
- [修复写回旧轮目录] → 调用方必须给出修复目录；旧目录的唯一计划读取不接收这次写入。
- [新分数沿用 5/9 或写成 9/9] → 分母来自逐名重读，遗漏保持遗漏。

## Migration Plan

先写范围。审核通过后按任务顺序改投影、隔离快照、再跑这两家。失败不回滚已归档观察。不能从本文件直接 enqueue。
