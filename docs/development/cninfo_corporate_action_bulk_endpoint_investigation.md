# CNInfo 公司行动结构化批量接口调查

## 结论

截至 2026-07-30，项目当前使用且能够验证的两个 CNInfo 结构化接口仍然是
逐证券接口，没有发现可安全替代它们的“市场级、日期有界、分页完整”的批量
接口。本次不增加猜测性生产代码，日更优化采用端点感知的定向逐证券请求。

## 已验证接口

### 历史分红送转

- AkShare 入口：`stock_dividend_cninfo(symbol)`
- CNInfo 路径：`/api/sysapi/p_sysapi1139`
- 已验证参数：`scode`
- 返回：该证券历史分红送转记录
- 限制：调用签名和当前请求均没有日期窗口或分页参数

### 配股实施

- AkShare 入口：`stock_allotment_cninfo(symbol, start_date, end_date)`
- CNInfo 路径：`/api/stock/p_stock2232`
- 已验证参数：`scode`、`sdate`、`edate`
- 返回：该证券指定日期范围的配股记录
- 限制：虽然支持日期范围，仍要求单一证券代码；当前契约没有市场级分页参数

## 未满足的生产准入条件

候选批量接口必须同时满足以下条件才能替换现有路径：

1. 明确支持 SSE/SZSE 市场范围或可枚举的证券集合；
2. 支持有界开始、结束日期；
3. 支持稳定分页，并能证明页间无重复、无遗漏；
4. 返回字段能够完整映射当前分红送转或配股观察表；
5. 在跨日新增、修订和撤回场景下有可重复的一致性结果；
6. 限流和鉴权行为能够纳入共享 CNInfo 自适应退避。

当前两个接口均不满足市场级分页条件。因此生产实现继续使用：

```text
公告/事件候选
  -> (instrument_id, source_profile)
  -> 对应的逐证券结构化端点
```

后续若 CNInfo 官方文档或可重复网络证据出现新的批量契约，应以独立 spike
验证分页完整性和限流表现，不能仅根据接口命名或单次响应接入生产。
