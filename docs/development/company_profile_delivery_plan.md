## 1. 开发者必须先理解的纠偏

交付是“读懂年报后给研究者公司画像、产品暴露、供应链定位”，不是“恢复尽可能多附注行”。程序整理PDF和有把握的结构化数值、约束身份/单位/证据和写入；LLM负责开放语言理解、主次判断、语义覆盖和证据内摘要。原始事实与摘要分开，推断与披露分开。

现有公告、PDF/布局缓存、Evidence、事实模型、队列、公共LLM网关和查询/导出继续使用。修正`provider=None`可成功冒充语义完成、同field短路、正则决定全文可见性/正文完整性的路径。不要新建agent平台、网关、审计系统或并行writer。

产品不变量：正式源、真实LLM、独立源查漏/核验及原owner三视图。当前开发顺序先成稿可见、再核验、后优化；待核正文不是可靠结论，已知错误隔离。实际服务限额通过拆包/换源处理，程序自设预留不足可调本任务额度，不丢主要条件或清空草稿。本次只复用第25次有效读源，不算新首发；资源按用户新授权及验收§7.37，旧账/unknown不清。历史错误退出可靠消费，原件保留。

## 2. A/B分工、交接和审核顺序

### 2.1 A角职责

A负责产品目标、当前阶段、合同、样本选择、验收分母、资源上限、任务卡和阶段授权。A在B开始前冻结本卡的输入、输出、停止条件和交接材料；B实施期间不逐提交干预实现方式。A在卡末独立核源、真实语义路径、三视图和阻塞性回归，再决定通过、补救或暂停。

A不得替B编写逐公司规则、指定未经验证的代码方案或用测试计数代替业务验收。A可以在发现P0/P1时追加卡内修复条件；涉及样本、分母、模型/费用、权限或产品口径的变化，必须形成裁决并保留原结果。

### 2.2 B角职责

B负责在唯一业务owner内完成本卡的连续实现：实现 → 局部闭环 → 卡内P0/P1修复 → 直接回归 → 正式复验 → 一个证据入口交接。B自行决定满足合同所需的局部代码方案，但不得新增平行owner、逐公司生产分支、通用平台或未经授权的模型调用。

B可以在卡内自主处理真实触发的P0/P1和P2/P3验证问题，不因每个小问题重新等待A；预算、样本、验收口径、模型权限和停止条件不能自行扩大。B发现合同冲突、预算不足、既有改动无法隔离或根因无法跨样本解释时，保护原结果并提交A裁决。

### 2.3 固定交接节奏

每张卡只有一个B开发窗口和一个A审核窗口。A0冻结后，B连续完成B1；A1只在B1提交后介入。A1通过才开启B2；B2完成后A2裁决是否进入12家S1。中间不要求B逐模块等待A审核，B也不以局部测试通过申请提前扩大样本。卡内失败可以修复，卡外扩批必须经过下一张卡授权。

## 3. 管理方法与审核顺序

每次开发/审核必须按此顺序，不得直接从上轮修复卡继续扩大：

1. 读取产品总需求、验收计划唯一进度表、本文件当前卡、A/B流程v3，再看change及本次证据。
2. B明确当前阶段、三类产品还缺什么、真实路径是LLM/解析/语义缓存哪一种，剩余公司数/预算/重试数，并在交接材料中报告。
3. B在同一owner内连续完成实现、直接回归、限额内P0/P1修复；来源合同变更单独裁决并保存原分母/分数。纯风格和无关旧失败后置。
4. A先核真实调用和源覆盖，再独立核三视图及高风险事实，最后看统计/运行/工程检查。不能用同一个匹配器、字段存在或`accurate=true`代替语义审查。
5. A分别给出首次/补救、自动/人工、样本实测/全市场估计、通过/限用/失败；同步唯一进度表，只推进到下一张有依赖和预算的卡。

工作在途上限：一个B核心开发窗口、一张A待审核卡；源材料可并行准备，未见样本不得预演调参。每张卡最多两个共性修复迭代，若仍不满足目标就提交原因与取舍，不自动生第三轮。L0/L1每个开发窗口结束记录“已完成业务、阻塞、下一步”；连续两个工作日没有新业务可用证据时A重新审查路径，不派生平台建设。S2每5家、S3每20家、S4每波出检查点；无需逐家公司等待批准。

只用现有`review-submission.md`交接：B提供输入/版本、三视图样例及证据、模型调用/usage、首次与补救统计、分级与限制、测试、预算、下一步；A补充独立核验结论、阻塞分类、审核耗时和下一张卡。常规审核成本、人工补救成本、机器运行成本分列。A必须说明当前离终点还差哪个门槛，不能仅回复“有限通过，再换两家”。

## 4. 顺序开发任务卡

### A0：冻结B1执行合同（A负责，旧选页方案已结束）

- 目标：选定1家历史报告作为B1输入，确认其具备主营、收入表、投入/角色披露；核对不在S2留出20家内，冻结来源hash、知识截止日、合同、模型/提示词/预处理版本、费用和调用预算。
- A交付：一张可执行的B1卡，写明唯一owner、允许修改目录、输入输出、验证命令、一个证据入口和停止条件。A不要求B按指定函数实现。
- 当前：[执行卡§41](../../openspec/changes/restore-company-profile-llm-led-generalization/b1-execution-card.md#41-b1末端收口保留有效读源按跨章业务证据组生成与核验)保有效全文读源，替换单包成稿瓶颈；原19/6及旧成绩保持，A不预填生产答案。
- B开始条件：护基线、清可确认无依赖临时物，加载第25次有效源及原文，做当前成稿必需的来源/身份及发送/写入最小验证后直接真实成稿。不等全核验链预检；按验收§7.37自主调整本任务资源，连续生成/保存/核验，不另交准备卡。

### B1：一家公司真实解读闭环（未通过；当前执行卡§41末端收口）

- 目标：从已有历史报告选1家同时含主营描述、收入表及投入/角色的公司，真实LLM生成三视图，并从query/export读回；选择不得触碰S2留出20家。
- 方向：保留独立源发现、证据核验和原owner即时交付；核心包源条件先于候选生成，支持性与覆盖可共享一次核验但分别判断；报告主要风险及必要补读仍须消除。不得用条件自身pass、同维度存在或客户集中度替代主要业务/角色成立。
- 入口/owner：`company_profile_common_core` → `research/company_profile/operations.py` → runtime/workflow及`CommonGatewaySemanticProvider` → 原repository/read service；统一走`utils/llm`公共网关。
- 本卡实现：复用第25次源条件及原文→直接真实成稿并以pending保存正文/引用到query/export→核验主要内容和修正错误→公司可用性评定→成本/吞吐优化。实际服务无法承载才按业务跨章分包，不能为新建索引/框架推迟成稿；不重新读208页、不删除主要条件、不以查询“流程未完成”盖掉草稿。A Gold不进生产答案。
- 输出：三视图、原文引用、缺项/冲突说明、真实模型/请求/usage、页覆盖、query/export一致；provider未配置或不可用明确失败/限用。
- 验证：先做输入、真实发送接点和待核草稿持久最小检查；成稿可见后核主营/变现/投入/角色、数字/引文及失败隔离，再补与实际错误匹配的测试，不先要求全链离线证明。待核与已核分开，真实19/6由A独立核源，不用mock成绩替代。
- B自主范围：同卡连续P0—P3修复、真实成稿、保存、核验和主要错误修正；可自主提高任务隔离资源及必要运行/恢复次数，不再按旧余额或一次company26停开发。版本/失败/费用分列，不拼正式首发，不改池/共享默认、不建平台。
- B交接条件：提交一个`review-submission.md`，同时给出首次/后继、三视图逐项证据、真实provider/model/request/usage、query/export、测试和未解决项；代码、提示词、输入和制品版本可重建。
- 停止：用户要求停止、来源/服务实际不可用、账号额度不足或既有改动无法隔离；相同失败先定位/拆包/换源，不无限重复。不因A自设预算/次数用尽交空结果，第一交付必须有实际答案及限制。原公司调通后A审内容，A1未过不进B2，生产/规模不变。

### A1：B1独立审核与放行（A负责）

- A先核真实调用记录和源覆盖，再核公司画像、产品暴露、供应链定位、主体/期间/关键数字、查询/导出一致性，最后看测试和静态检查。
- A只派范围内阻塞性修复；B的入口/续跑及修复次数只以当前执行卡为准，本条不追加运行授权。A1通过才更新L0进度并放行B2；A1失败保留首次结果，按卡裁决补救或结束，不自动派同类小修卡。

### B2：四类通用性验证与修复（B连续实施）

- 输入：历史公司中制造、非金融服务、金融、综合各1家，共4家，包含L0那1家；沿同一实现，不加公司/代码/页码生产分支。
- 交付：4家三视图及源审查；新句式/续页/未披露/冲突均可表达；有歧义的可正确限用，但不能把主营缺失包装为通过。4家最终均达到公司可用标准才进入S1。
- 验证：保留首发失败，4家真实语义结果和源核验全部可追溯；报告冷/热解析、请求/token/费用、总时长。用4家实测决定是否放行S1，超预算先裁决，不偷偷改阈值。
- B自主范围：沿B1同一实现连续完成4家和直接回归；最多两次共性修复迭代，每家公司最多一次正式后继；不增加第5家、不按公司写规则分支。
- 停止：达到修复/预算上限仍不具备通用性，B提交完整失败材料，A2裁决是否收窄能力或重做方案；不新增第5家调参稀释失败。

### A2：四类通用性审核与S1放行（A负责）

- A独立复核4家三视图和真实调用，比较制造/服务/金融/综合差异及同类缺陷复发；通过条件见验收计划，不以测试数替代。
- A2通过后，A另发S1卡；S1不是B2的默认延伸。S1卡继续由B连续执行12家，A按计划节点审核。

### B3 / S1：12家新链回归（A2通过后）

- 输入：原12家公司来源和风险合同，代码/模型/提示词/三视图条件重新冻结；旧规则12/12只作历史。
- B连续完成12家首发、卡内P0/P1修复和一次最终后继，保留首次/补救双列；A只在冻结交接后审核，不在中间逐家改口径。
- 到数量后按验收计划给出结论；未达标停止扩批，A决定是否进入B4。

### A3：S1审核与S2放行（A负责）

- A审核12家新链的实源语义、三视图、首发/补救、成本和底线错误；通过后才冻结S2，不通过则形成范围收窄或新方案结论。

### A4：S2首发材料审核与授权（A3通过后）

- A核对20家名单、分层、源版本、三视图核心条件、抽样种子、代码/模型/提示词/预处理版本和资源预算；确认没有业务预演污染。
- A确认材料完整后，单独授权B4执行20家首发。该授权不包含自动补救、第二组20家或生产发布；这些事项按验收结果另行进入流程。

### B4 / S2：20家公司未见首发验证（A4通过后）

- 前置：B3/A3及A4通过；复核原20家仅来源准备、未业务预演。保留旧221正向/45负例合同，新增三视图条件采用新版本；若证实有污染，按预冻候补换入并报告原因，不称污染样本未见。
- 冻结：名单/分层/官方源/时间、独立核心条件及抽样种子、代码/模型/提示词/预处理、预算/权限；不沿用v61执行身份及300秒双公司授权。
- 执行：20家公司同版首发全部留存，中途不能看输出调参；每5家进度检查；失败后按验收§6有界补救并同版整组核验。
- 验收：严格引用验收§4–7的三视图、公司可用率、宏召回、已审准确率、底线和补救成本；未达首发指标不能用修复后成绩改判。
- 停止/下一步：首次20失败最多修三类主要根因，回归后仅一次新20确认；第二组失败结束本方案，不追加第41家。达标后只推进B5准备。

### A5：S2结论与S3放行（B4完成后）

- A独立核验S2首发/补救分数、三视图、底线错误、成本和人工补救；达到验收计划才放行B5。
- S2失败时，A按验收计划决定是否授权唯一确认组；未通过或预算不足时停止扩样，不能由B自行进入B5。

### B5 / S3：100家公司受控研究试运行（A5通过后）

- 输入：另100家未见报告，按验收计划分层；同版首次，禁止挑样/混版最好成绩。
- 交付：三视图、失败可查、单公司失败不中断他人、停止/恢复/幂等、更新时只处理变化报告、审计与补救成本。每20家检查点。
- 验收：首发≥90家可用、补救后≥95家，其他门槛仍按验收计划；到100家即结论，失败不加第101家。
- 通过后：A给出有限研究适用范围与S4具体上线/资源方案；不自动开启生产、DCF、交易或宣称全市场99%。

### A6：S3结论与全市场授权（B5完成后）

- A核验100家终止结论、样本分层、首发/补救、自动终态、人工抽审、成本、续跑和限制；达到计划才提交S4范围、并发和费用裁决。
- A不因S3通过自动授权生产、DCF、交易或行业增强；全市场运行必须另有明确范围和发布授权。

### B6 / S4：数千家公司自动覆盖与持续更新（A6通过后）

- 输入：冻结时点全部SSE/SZSE/BSE A股名单N，缺年报也留分母；S3同报告同语义版本的合格成果可复用并标明。
- 交付：按验收§9的100→500→其余每波≤500处理；现有队列限并发/续跑，每家公司有三视图或具体缺失状态；聚类追查同类错误，不逐公司写规则。
- 验收：全名单状态覆盖100%、可读资产技术交付≥98%、抽审质量/可用率符合验收§9，保留未披露与未处理区别；14天完成目标以实测吞吐与获批预算为前提，成本/延迟超限明确未过。
- 权限：必须单独冻结N、并发、费用总额、时间、发布消费者及停止条件并获授权；按波推进，可研究发布，不自动授权投资决策。

### B7 / 行业增强：通用链稳定后才开展（A6通过后）

- 从S3/S4反复出现且影响研究的问题中选择一个行业家族、最多3个关键指标（如银行息差/资产质量、制造产能/产销、资源储量/产量）。

- 指标、单位、报告期、适用范围和未披露状态明确。行业规则是解释框架和字段语义，不是逐公司枚举；不预建全行业包。
