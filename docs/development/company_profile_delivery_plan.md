## 2. A/B分工、交接和审核顺序

### 2.1 A角职责

A负责产品目标、当前阶段、合同、样本选择、验收分母、资源上限、任务卡和阶段授权。A在B开始前冻结本卡的输入、输出、停止条件和交接材料；B实施期间不逐提交干预实现方式。A在卡末独立核源、真实语义路径、三视图和阻塞性回归，再决定通过、补救或暂停。

A不得替B编写逐公司规则、指定未经验证的代码方案或用测试计数代替业务验收。A可以在发现P0/P1时追加卡内修复条件；涉及样本、分母、模型/费用、权限或产品口径的变化，必须形成裁决并保留原结果。

### 2.2 B角职责

B负责在唯一业务owner内完成本卡的连续实现：实现 → 局部闭环 → 卡内P0/P1修复 → 直接回归 → 正式复验 → 一个证据入口交接。B自行决定满足合同所需的局部代码方案，但不得新增平行owner、逐公司生产分支、通用平台或未经授权的模型调用。

B可以在卡内自主处理真实触发的P0/P1和P2/P3验证问题，不因每个小问题重新等待A；预算、样本、验收口径、模型权限和停止条件不能自行扩大。B发现合同冲突、预算不足、既有改动无法隔离或根因无法跨样本解释时，保护原结果并提交A裁决。

### 2.3 固定交接节奏

每张卡只有一个B开发窗口和一个A审核窗口。A0冻结后，B连续完成B1；A1只在B1提交后介入。A1通过才开启B2；B2完成后A2裁决是否进入12家S1。中间不要求B逐模块等待A审核，B也不以局部测试通过申请提前扩大样本。卡内失败可以修复，卡外扩批必须经过下一张卡授权。

## 3. 管理方法与审核顺序

每次开发/审核必须按此顺序，不得直接从上轮修复卡继续扩大：

1. 读取产品总需求、验收计划唯一进度表、本文件当前卡、A/B流程v3，再看change及本次证据。
2. B明确当前阶段、三类产品还缺什么、真实路径是LLM/解析/语义缓存哪一种，剩余公司数/预算/重试数，并在交接材料中报告。
