## 2. 产品目标

为 SSE、SZSE、BSE 的全部 A 股自动生成可持续更新、结构化、可核验的公司核心画像及基础商品暴露。全市场是证券池覆盖目标，不要求每家公司每个字段完整，也不允许用少量零散事实冒充骨架完整。

用户应能回答：公司做什么、主要产品/服务和板块、怎么赚钱、基本规模、明示投入和销售对象、商品关联及业务角色、近期重大变化。事实、程序推导、研究假设分开。生产审批只针对实际消费范围；研究数据库发布不自动授权 DCF 或交易。

## 3. 第一版范围与核心骨架

### 3.1 通用核心骨架（全行业）

| 维度 | 最小可用内容 | 缺失的影响 |
| --- | --- | --- |
| 主营业务 | 有来源的主营说明/经营模式；模板摘要保留原文链接 | 缺失时骨架不完整，其他事实仍可交付 |
| 产品/服务及板块 | 来源明确的主要产品、服务或业务线，保留原名 | 不因行业目录无别名就丢失原文业务 |
| 收入来源 | 主要收入产生方式；如披露业务构成，保留主要分项和占比 | 未披露金额不编造；原文明示单一业务可形成定性骨架 |

三维都得到有证据的实质回答才标记骨架完整；合法未披露、零条事实或大量无关数字不计为三维回答。骨架完整只代表基础阅读可用，不代表所有数值已被逐条人工核验。业务描述不得由产品行业常识生成。

### 3.2 按披露补充

规模优先复用已有正式财务事实，按公司/期间/知识时点连接，不再抽一套财报。分部收入成本毛利、适用经营指标、投入品、渠道/客户类型、具名对手/集中度、业务变化和商品关联按实际披露收集。产能、库存、门店、用户、监管指标不成为全公司必填。

### 3.3 边界

第一版包含基础商品暴露（§20），不包括无依据的净利润敏感性、价格预测、传导率、完整供应链网络、DCF 自动参数或港股。行业增强未研究不阻塞通用三维画像。

## 4. 事实分层与自动接受

复用 `reported_fact`、`deterministic_derivation`、`research_assumption`。证据和校验通过的事实可以由程序自动接受，无需逐条人工批准；LLM 本身不能写 approved。

新生产 writer 接通前，数据仍为 `accepted_for_review` / `research_fixture`。生产切换后，由同一应用 owner 按明确版本的自动接受规则将合格事实写入新契约空间。机器判定、规则版本和依据可追溯；矛盾项隔离，不用平均分消除错误。

## 5. 总体业务说明

复用 BusinessOverview，定位主要业务/经营模式语义章节，保留原文、页码、版本和可得日；不硬编码第三节。可用模板摘要，但不增加原文没有的数字、产品、角色或因果。一个 Activity 动作枚举无法匹配，不得连同已成立的业务总述一起丢弃。

## 6. 通用信息对象

继续复用 Company、BusinessOverview、Segment、Activity、Measurement、Relationship、BusinessEvent、BusinessRegime、IndustryPackageAssignment、Evidence、CoverageResult；商品输出复用/适配 CommodityExposure 和有限 ValueChainRole 职责，不新建同义对象体系。

Activity 描述行动，Measurement 描述单一指标。Measurement 同时绑定对象、metric/logical_slot、物理锚点、单位、期间及比较口径。收入/销量、库存量/库存金额、产能/产量不能混合。Segment 调整行不能当普通产品；`consolidation_adjustment` 保留独立金额，不能加总成重复集团收入。

未知产品/服务名保留 source-native；无法映射的行业专有数值保留来源与待映射状态，不强塞已知 metric，也不悄悄扩 schema。未知标准化标签不阻塞其他事实和基础文本骨架。

## 7. 覆盖、完整性与交付

保留 `required / conditional / optional / not_applicable_by_design` 和 `observed / not_disclosed / not_applicable / extraction_failed / unclear` 两个维度。required 表示必须检查并报告结果，不等于公司必须披露。

- 记录层：值、单位、对象、证据或期间错误隔离；其他 accepted 事实继续交付。
- 公司层：三维骨架完整性与补充字段 coverage 分别展示；可交付部分画像。
- 任务层：运行、完成、待重试、失败与画像完整性分离；允许执行结束且骨架不完整。
- 批次层：逐家公司保存，不因个别失败阻止整个证券池。

章节跨 scope 汇总须匹配对象、期间、指标和披露义务，同字段名不足以相互补齐。缺页/未读/预算失败不是未披露；未发现商品关联不是零暴露。旧 hold 原义保留在历史 bundle，不据此封锁新事实级读取。

## 8. 来源、优先级和时间语义

正式交易所/CNInfo 披露为公司事实权威，已有可追溯正式结构化事实可复用。聚合源用于发现/校验/candidate，不能把正式抽取失败冒充成功。无需新增文档下载链。

更正仅在明确范围覆盖原稿；新公告按有效期与知识可得日形成后继，不重写历史。每条事实保留报告期、published_at、文档版本和有效/知识时间；同名不同对象、不同期间、不同来源锚点不静默合并。官方表格与叙述冲突先核对象、期间、口径和单位，无法解释保持 unclear。

## 9. 年报章节家族

通用基础需要主营/产品服务/收入来源的语义片段；行业增强按触发条件增加分部、经营量、材料、对手和事件。复用现有章节任务和 selector，允许按需要局部扩展，不能把制造六章固定清单套给金融/TMT。

程序自动选取页段与续表并记录证据，不要求每家公司人工冻结选页。只将完整必要上下文传给相应任务；读不到的章节显式报缺，不以搜索词命中替代 owner 判定。

## 10. 确定性解析与 LLM 分工

优先复用已有合格事实和完整结构化表格；可靠数值无需重复让模型抄写。既有解析不能正确处理的上下文直接用有界 LLM，不为启用通用骨架先建设新解析平台。校验只能确认实际输入，不能用 Gold 补答案。

## 11. LLM 合同与运行预算

仅 extract、typed repair、独立 verify；程序生成复核包。请求携带身份、活跃字段、完整证据及允许语义，禁止外部公司知识补事实。source-native 不由模型换算；程序拥有 canonical 转换。

沿用公共逻辑池、动态 scope token 预算和共享绝对 deadline。传输/协议失败允许有界模型切换，语义争议不能靠换模型投票强过。可恢复任务在总尝试/时间/调用预算内延期重试，达到上限交付缺项并继续其他公司。

## 12. 指标、动作和标准化

已有度量及动作枚举继续复用；develops、produces、processes、sells、purchases、provides_service、operates 与数值分离。收入、成本、毛利、产能、产销存、加工量分属独立字段；字段扩展需要明确语义和代表证据，但不要求新增整套平台。

processing_volume 仅表示对外加工服务量，委外采购、内部工序和自营回收不能套用。未知动词可保留原文及候选解释，不新增未校验 canonical action。

## 13. 唯一主体政策

保留 subject_scope / subject_basis，无平行置信度或主体枚举。按局部证据依次判定：

1. 明确仅母公司/本公司单体为 issuer；具名子公司为 named_subsidiary；明确业务分部为 business_segment。局部更窄证据优先于报告封面集团表述。
2. 明确合并/集团为 consolidated_group + direct_source_wording。
3. 已完成同报告合并数值核对可为 consolidated_group + numeric_reconciliation_to_consolidated_statement，保留核对页和依据。核对不是普通事实接受前提。
4. 原文仅称“公司”或没有明确更窄范围，也没有主体冲突时，程序采用 consolidated_group + report_default_group_scope；保留原文，不伪装为直接合并证据。
5. 明确冲突、多主体不可区分或非本公司行动者无法归属时保持 unclear。默认规则不能把第三方行为改成上市公司行为。

同表局部证据可共享，不跨无关表传播。Gold、verify、行业合同和 projection 均采用本条；历史 Gold 冲突单列，不为当前接受强制把已支持的 group 降回 unclear。

## 14. 数值、单位和比较

保留 source value/unit/header/qualifier 和原文存在的脚注；原文无脚注不制造。程序执行有限、有记录的等价转换，不按量级猜单位。duration、instant、event 分开；预计完工时间只进 qualifier，不覆盖 reported_period。重述列带 comparison_basis，与原公布数据并列。

相同量纲/对象/期间/口径才可比较；集团默认主体不自动使分部、抵消行、不同产品或不同 capacity_kind 可相加。历史事件单向等价仅限其已批准条件，不建任意模糊 matcher。

## 15. 错误处理与质量评价

关键数值/单位/期间/主体冲突、证据错绑、第三方行为混淆隔离到实际受影响记录。解析失败保留缺项，完整性不足不封锁无关记录。匿名身份保持 report-local，不能跨报告合并。仅合计披露不生成对手名称或 Relationship。

人工正常职责为抽样和冲突裁决，不是每家公司上线前逐条审批。缺乏证据的推断即使“概率较高”也不能当披露事实。

## 16. 全市场基础与行业增强

A 股通用基础包自动适用于全部行业。制造/材料、资源、能源公用、消费零售、一般服务、金融、医药、TMT 是增强家族，不是基础采集白名单。

行业增强只激活本报告可支持的指标；未经实现的增强记录未支持，仍交付基础骨架。行业目录未知、复杂业务组合或转型不剔除证券，先保留通用内容及增强待判定原因。

## 17. 按报告期分配增强包

复用现有正式分类作候选，以报告主要业务、板块和事件证据决定适用增强。原文主导业务和更窄分部优先；未知组合退回基础包，不能强套最近行业。没有已确认 regime 日期不阻止本报告基础画像，但不得回填历史生效日。

## 18. 行业研究与登记

独立行业文档定义指标、模板、触发、单位、正反例与小型验证；这是增强范围的验收，不是全行业基础采集前置审批。固定 Gold 只用于其版本回归；运行中发现新形态形成共性修复，不做无限公司专项补丁。

当前：通用模型已实现但跨行业基础任务待接入；制造/材料研究基线已形成；其他增强待实现/验收。不能把文档登记或八报告 CSV 导出等同全市场能力。

## 19. 单一执行链与任务

证券池/有效正式年报 → 增量入队 → 自动 Evidence → Stage 5 语义 owner → 记录接受/隔离 → 新契约持久化 → 骨架及商品关联 → 查询/画像/导出。

复用现有队列、租约、checkpoint、源资产和 gateway；禁止并行新旧 writer 写同一事实空间。幂等键覆盖证券、报告版本、输入范围和处理政策身份；规则升级只重做受影响任务，不一键重跑所有公司。

提供预览、运行、状态、暂停、继续，入口名在接通并测试后发布；旧 backfill 名称不能默认为已接 Stage 5。按时间/调用预算工作，默认结果复用；不要求指定公司、不要求凑齐50家。完成 scope 即保存，失败续跑不重复已经完成的 scope。

## 20. 基础商品暴露与有限价值链角色

近期交付必须包含：公司/业务对象、商品标准标识或待映射原名、原文产品/投入名、产品销售/原料投入/能源消耗/套保等证据支持的角色、来源事实引用、期间/知识时间、可用性与不确定性。数量和强度披露则保留，未知留空。

角色与映射由程序按事实和版本规则产生，标记 deterministic_derivation，不伪装为原文。商品/产品映射一对多无法确定时显示待映射，不猜一个标的。一个商品可同时有收入端和成本端角色，不能无数量基础净额化。

商品存在但行情未绑定时仍交付关联；价格序列是独立市场数据域。投入成本端不等于净利润负相关，产品销售端不等于净利润正相关。净利润弹性、传导/滞后、套保有效性、价格预测独立研究，不阻塞基础商品关联。

不是所有公司都有重大商品暴露。完整检查后无证据则显示“未发现明示关联”；未检查或失败显示对应状态，二者都不能表示零暴露。有限价值链角色以实际输入/输出/服务证据为限，不承诺完整产业链。

## 21. 使用与发布边界

当前研究数据可按既有受限用途读取；新生产任务上线后通过明确的新契约 writer/读取范围启用“公司事实＋基础商品关联”的研究发布。每条记录接受与消费者授权分离；自动审核无需逐条人审，人工覆盖争议与抽样。

DCF、交易、价格预测不在本 change 自动启用范围。not_authorized 是当前环境边界，不是永久产品终点；批准规划本身不改变配置，实施 tasks 必须包括具体发布接入和上线验收。

## 23. 全 A 股覆盖与缺资产

日常采集可以复用历史已验证公司，不使用 OOS 排除清单。评测留出样本单独管理，不与生产选样混用。

## 24. 迁移、清理与回滚

新契约空间独立落地，复用 raw assets 和运行底座，不兼容错误旧语义。先提供新读取和 writer 的明确范围切换；再按确切旧语义清单清理。全量 reset 不阻塞新空间研究交付。

旧 writer 始终禁用；切换失败停止新写入并保留已保存正确记录，不能回滚为旧错误语义生产。删除清单必须说明对象/依赖/可恢复性，保留正式 PDF 和原始证据。本轮仅删除失效文档/派生审计，不执行数据库清理。

## 25. 历史 Stage 5 的定位

阶段 0—4 是冻结、研究和语义基础；Stage 5 是制造/材料隔离竖切，不是全 A 股产品的全部验收。原四报告权威与后续 OOS/batch 各保持原 run 和结论，离线 Gold 只说明相应版本的匹配情况。

已撤回的 a3dc726 派生审计不能证明101条语义全对或五类缺陷零复发。原始运行结果和撤回说明保留；重复的当前状态汇总退出产品索引。新的语义审查纳入真实任务结果抽样，不再触发旧“再跑一次全套”待办。

| M3 基础商品暴露和研究发布 | 商品与业务角色、期间和来源可查，未绑定行情仍可用 | M1事实＋M2持久化；明确映射/读取契约、范围切换，不等净利润模型 |
| M4 行业深度与市场扩展 | 按真实缺口增强关键指标，扩大吞吐 | 基础任务持续交付；逐项验证增强，不要求全部公司齐全 |

M1—M3 是近期同一产品闭环，在当前 change 分段实现。M4 为后续迭代。旧阶段6 reset 变为M2/M3切换后的清理工作，旧阶段7增强与基础生产解耦，旧阶段8生产不再排在所有增强之后。

## 27. 验收与扩大运行

规划验收与运行验收分开。实施必须证明：全A股候选分母可解释；三维骨架可核验；事实错误隔离；保存/查询/续跑正确；商品关联可用；身份/时间/单位正确。

业务质量看三维骨架覆盖率、来源已披露的重要信息召回、来源抽样准确性、关键数值错误、时效、耗时/token和人工工作量。召回分母由独立阅读样本来源确定，不能用模型自己列出的字段充当全部已披露信息。按行业和披露形态分层报告，不能以大量细小表格记录掩盖主营缺失。

不预设“50家全通过/Gold24全等/所有负例真实触发/人工项清零”。fixture守卫与真实样本结果分列，未触发不算通过。抽样规则和首次扩大运行的数值阈值须在观察结果前明确写入运行计划；阈值未确定或样本不足时不得声称规模质量达标。已接受事实的研究交付不依赖上述推广判定。
