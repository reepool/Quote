## 2. 产品目标

为 SSE、SZSE、BSE 的全部 A 股自动生成可持续更新、结构化、可核验的公司画像、产品暴露和供应链定位。全市场是证券池覆盖目标，不要求每家公司每个字段完整，也不允许用少量零散事实冒充骨架完整。

用户应能回答：公司做什么、主要产品/服务和板块、怎么赚钱、基本规模、明示投入和销售对象、商品关联及业务角色、近期重大变化。事实、程序推导、研究假设分开。生产审批只针对实际消费范围；研究数据库发布不自动授权 DCF 或交易。

## 3. 第一版范围与核心骨架

### 3.1 通用核心骨架（全行业）

| 维度 | 最小可用内容 | 缺失的影响 |
| --- | --- | --- |
| 主营业务 | 有来源的主营说明/经营模式；模板摘要保留原文链接 | 缺失时骨架不完整，其他事实仍可交付 |
| 产品/服务及板块 | 来源明确的主要产品、服务或业务线，保留原名 | 不因行业目录无别名就丢失原文业务 |
| 收入来源 | 主要收入产生方式；如披露业务构成，保留主要分项和占比 | 未披露金额不编造；原文明示单一业务可形成定性骨架 |

三维都得到有证据的实质回答才标记骨架完整；合法未披露、零条事实或大量无关数字不计为三维回答。骨架完整只代表基础阅读可用，不代表所有数值已被逐条人工核验。业务描述不得由产品行业常识生成。

### 3.2 按披露补充

规模优先复用已有正式财务事实，按公司/期间/知识时点连接，不再抽一套财报。分部收入成本毛利、适用经营指标、投入品、渠道/客户类型、具名对手/集中度、业务变化和商品关联按实际披露收集。产能、库存、门店、用户、监管指标不成为全公司必填。

### 3.3 边界

第一版包含产品/服务收入端、投入成本端暴露和有限供应链定位，以及基础商品关联（§20），不包括无依据的净利润敏感性、价格预测、传导率、完整供应链网络、DCF 自动参数或港股。行业增强未研究不阻塞通用三维画像。

## 4. 事实分层与自动接受

复用 `reported_fact`、`deterministic_derivation`、`research_assumption`。有原文支持的LLM摘要是披露事实的可读表达，另留摘要生成方式、模型/提示词版本与支持引用；模型归纳的角色或映射须标为解释/待核，不冒充程序确定性推导或直接披露。不新增一套平行事实对象；必要元数据通过版本化现有投影接续。证据和校验通过的事实可以由程序自动接受，无需逐条人工批准；LLM 本身不能写 approved。

新生产 writer 接通前，数据仍为 `accepted_for_review` / `research_fixture`。生产切换后，由同一应用 owner 按明确版本的自动接受规则将合格事实写入新契约空间。机器判定、规则版本和依据可追溯；矛盾项隔离，不用平均分消除错误。

## 5. 总体业务说明

复用 BusinessOverview，定位主要业务/经营模式语义章节，保留原文、页码、版本和可得日；不硬编码第三节。可用模板摘要，但不增加原文没有的数字、产品、角色或因果。一个 Activity 动作枚举无法匹配，不得连同已成立的业务总述一起丢弃。

## 6. 通用信息对象

继续复用 Company、BusinessOverview、Segment、Activity、Measurement、Relationship、BusinessEvent、BusinessRegime、IndustryPackageAssignment、Evidence、CoverageResult；商品输出复用/适配 CommodityExposure 和有限 ValueChainRole 职责，不新建同义对象体系。

Activity 描述行动，Measurement 描述单一指标。Measurement 同时绑定对象、metric/logical_slot、物理锚点、单位、期间及比较口径。收入/销量、库存量/库存金额、产能/产量不能混合。Segment 调整行不能当普通产品；`consolidation_adjustment` 保留独立金额，不能加总成重复集团收入。

未知产品/服务名保留 source-native；无法映射的行业专有数值保留来源与待映射状态，不强塞已知 metric，也不悄悄扩 schema。未知标准化标签不阻塞其他事实和基础文本骨架。

## 7. 覆盖、完整性与交付

保留 `required / conditional / optional / not_applicable_by_design` 和 `observed / not_disclosed / not_applicable / extraction_failed / unclear` 两个维度。required 表示必须检查并报告结果，不等于公司必须披露。

- 记录层：值、单位、对象、证据或期间错误隔离；其他 accepted 事实继续交付。
- 公司层：三维骨架完整性与补充字段 coverage 分别展示；可交付部分画像。
- 任务层：运行、完成、待重试、失败与画像完整性分离；允许执行结束且骨架不完整。
- 批次层：逐家公司保存，不因个别失败阻止整个证券池。

章节跨 scope 汇总须匹配对象、期间、指标和披露义务，同字段名不足以相互补齐。缺页/未读/预算失败不是未披露；未发现商品关联不是零暴露。旧 hold 原义保留在历史 bundle，不据此封锁新事实级读取。

## 8. 来源、优先级和时间语义

正式交易所/CNInfo 披露为公司事实权威，已有可追溯正式结构化事实可复用。聚合源用于发现/校验/candidate，不能把正式抽取失败冒充成功。无需新增文档下载链。

更正仅在明确范围覆盖原稿；新公告按有效期与知识可得日形成后继，不重写历史。每条事实保留报告期、published_at、文档版本和有效/知识时间；同名不同对象、不同期间、不同来源锚点不静默合并。官方表格与叙述冲突先核对象、期间、口径和单位，无法解释保持 unclear。

## 9. 全文发现与必要上下文

每份新报告先由程序建立覆盖全部物理页的结构索引及待导航状态，区分正文、表格、附注、目录及不可读页面；程序不据此代替开放语义判断。LLM分批导航选择主要业务、产品/服务、变现机制、投入/渠道和关键变动的相关上下文，读取完整段落、表头、单位、脚注及必要续页；结合可靠收入构成与至少一次独立上下文的源先行查漏，决定有界补读。不得仅用旧正则、公司/页码清单或固定标题决定模型能看什么；陌生章节、预览外原文及未选页面必须有模型请求补读的通路。导航选择由真实LLM作出，程序只打包、追踪覆盖及执行硬约束。

**导航与业务交付渐进交错执行。** 一批导航得到可读核心上下文后，先生成正文候选，按实际候选及必要上下文组成证据单元，逐单元独立语义核验并经原owner持久查询，再推进下一核心包；不得要求所有导航或整包源清单成功才允许首条核验。报告级独立无候选源审负责找遗漏，不能用候选核验代替，未完成时报告完整仍为false。LLM依据产品核心而非自然页码顺序决定阅读优先级，可从当前正文和全报告结构优先补读收入构成、变现机制、投入或角色上下文；不新增规划平台。局部故障只隔离对应范围和依赖，全局预算内继续独立核心工作，任何全局硬限到达仍须停。

全部页面须在覆盖记录中有去向，分别记录导航/预览已检查、相关正文已读、未读、不可读及补读原因；导航覆盖不等于全文已读。完整年报是分析资产范围，不要求把全部可读附注正文逐字发送后才允许交付核心画像，也不要求逐附注行抽取。主要板块与关键变现机制必须实际读源并进入漏项检查，未读或预算失败不能写为未披露。扫描/乱码页走现有定向OCR或布局解析，未恢复则标缺口。模型不得执行报告中嵌入的指令、工具请求或外部网址，报告内容仅作为待分析数据。

核心可用性、全文阅读覆盖和补充字段完整性分别评估：有证据的三视图核心可以成立，同时报告部分附注未读；若已发现主要板块、关键金额/主体或必要上下文尚未读/未核，则核心仍不完整。未完成导航范围不能静默按普通附注排除；须经后续导航或有源依据的独立漏项核验消除主要业务风险，否则公司仍限用，但独立已核部分可查。仅地图成功、模型自报完成、字段存在或任意抽样不能直接把核心判完整。分层阅读仍可能遗漏未被导航识别的披露，这属于必须在独立源审及20/100家未见样本中检验的召回风险，不承诺零遗漏；疑似主业缺口须有界补读，仍不清楚则限用/隔离。旧冻结轮次的合同和成绩不按本条重判；v5只约束后续显式启用身份，不恢复任何历史运行授权。

### 9.1 核心映射与摘要

保留主营、产品服务、收入来源三维及现有ChapterTask/事实对象；以版本化请求/响应补充“全文证据地图、源先行核心条件、语义覆盖、证据摘要”，先更新schema和消费者再启用，不偷偷向v1返回未知字段。extract/repair/verify沿既有provider接续，不为三维重复调用三次，不新建多agent平台。

每个维度记录支持对象/证据、实际回答、缺项/冲突及覆盖范围。语义是否实质回答、主体/计划/否定/期间、未披露与遗漏的区别，由完整上下文的语义阅读和复核判定。程序检查引用和状态依赖，不能凭字段存在、关键词命中或固定句式把维度标完整。允许证据内抽象和通俗归纳；原文原名原数值另存，不由摘要覆盖。

### 9.2 引用定位与语义支持分开

证据必须定位到本次实际发送的报告/页/片段原文。PDF换行、排版空白与模型引文的空白差异可用保留字符位置映射的规范化定位，随后回填原文中的连续精确片段、偏移和原始模型引文；不改写源文或旧响应。非空白字符仍须一致，不能删标点、负号、数字、主体、否定或时态来凑匹配，不能在未发送的全报告里猜出处。多处匹配且上下文不能消歧时保持未定位，不能静默任选。

定位成功不等于语义成立。后续合成/核验须能看到所属段落、标题及必要限定，区分行业环境与公司经营、战略目标与已实现身份。单条定位/核验失败隔离该条件及依赖，保留独立有效结果和原回执；若影响主要板块则核心仍不完整。可在卡内恢复额度中定向补读/修复，不能为一条排版差异清空整家公司，也不能将未定位证据直接接受为事实。

PDF的换行不等于语义段落边界。上下文打包不得截掉统领后文的行业/主体、时态、否定或表头限定；引文与上下文分开保存，以源偏移和段落/布局复原必要范围。无法在有界载荷中恢复限定时，该主张保持待核或定向补读，不把失去限定的短句交模型后当作可靠核验。程序只恢复原文范围，不据标题关键词直接裁定公司行为。

## 10. LLM 与程序分工

| 工作 | 权威职责 |
| --- | --- |
| 正式源/解析/布局/数字 | 程序获取和整理；可靠结构化表格及已有财务事实直接复用，保留物理锚点、单位、期间、主体 |
| 开放语言解读 | LLM识别公司业务、主次板块、动作、否定/计划、关系和不确定性，生成证据支持的摘要 |
| 完整性与语义复核 | 从源内容先建立主要业务清单，再与候选对照；不只检查候选，也找遗漏；A独立核原文 |
| 硬约束 | 程序检验schema、精确身份/引用、原数值与换算、权限和预算；不把启发式正则当语义真值 |
| 交付 | 原owner处理接受/限用/隔离、持久化、查询/导出；LLM不直接写approved或修改数据库 |

每份新报告核心语义必须真实调用配置的LLM。已有同field记录不能短路阅读；无provider/超时/失败须明确缺语义，不能静默用规则输出冒充新路线成功。只有报告hash、输入范围、处理/模型/提示词版本一致且已有合格语义结果时可复用；复用轮可0调用，但须链接原真实调用与覆盖证明。新验收首发冻结禁止复用语义结果；PDF解析缓存可保留。

开发接续与合格画像复用分开：A可在当前卡明确允许兼容重验同报告的原导航或真实待核候选，保留来源/实际发送范围/模型/请求/提示词和版本链。导航仅选范围，旧候选仍待核；必须由新窗口的真实语义核验才能成立可靠主张，不能改旧结果或称新首发。正文补读、报告查漏及未完成核验仍须实际完成。成功阶段沿现有checkpoint保存，已核独立结果不被无关失败抹去；接续范围及预算由验收计划冻结，不据此宣称通用续跑已验收。

分批是可恢复的业务交付单元，不能只是请求拆包。每批仅合成该批原文支持的维度；核验按真实生成目标重新打包，只携带有关主张、确切引文及所属段落/表头/单位/限定、实际依赖记录。无需把整包源条件、全部页及无关记录重发；不能裁掉语义限定或用假目标预估代替实际载荷。单目标仍超限时定向恢复必要上下文或保持待核，不能截断证据、悄悄丢目标或提高限额。每个成功核验单元立即持久可查，再继续下一单元；缺检查、冲突及模型自报observed不得晋升。后续失败保留独立已核部分，真实冲突只撤回有关依赖。

报告级七维要求在各批合并后评估，不要求每个局部批次生成七维占位答案。销售产品/服务与客户类型、经营/服务角色可以作有引文的定性归纳，缺集中度、金额或原文未使用“产业链角色”等术语，不构成拒绝这些已有内容的理由；未披露的补充指标另列。不得把证据内解释扩成猜测采购关系、具名对手、已完成转型或价格/利润敏感性。

规则用于有把握的结构化内容、硬约束和风险提示，不新增公司名/证券代码/页码专属生产抽取分支。测试可以使用真实失败样本，修复必须解释其可跨公司的格式或业务原因。

## 11. 模型核验与运行预算

复用公共LLM池及extract/repair/verify能力。**可信度与覆盖分开。** 逐证据单元核验判断主张是否被原文支持；报告级源先行查漏在不提供候选答案的独立请求中，从全报告结构、核心完整上下文及可靠收入构成建立主要业务清单，再与草稿对照并定向补读。该查漏可在首批核验后执行或按范围分批，不再对每包重复设为首条核验的前置。报告主要源条件仍须逐项语义核查，主要板块、必要补读或独立查漏未完成不能标公司完整；局部已核不等于报告完整。验证可以使用同一模型的独立上下文，但不称为统计独立或真值保证；A仍独立审源。核心摘要和高风险数字/主体/时态全查，次要明细抽查，不重复核全份大表。

报告级查漏必须闭合到实际交付：无候选源审只负责独立发现主要条件；随后把这些条件与已核主张、相关原生事实及其必要证据进行语义对照。条件pass必须指出实际覆盖该条件的已核交付对象，程序只核对引用存在、合法状态和依赖，不能按同维度或关键词代替语义覆盖。只确认“原文存在该条件”、未携带可对照交付、引用无关对象或遗漏同维度另一主业，都不能消除该主要缺口。不得把逐条重读源条件代替这一对照，也不能由A Gold生成运行时答案。

程序能拒绝无锚点/数值不一致等硬错误；语义冲突保留双方证据，定向补源/复读一次后仍不清楚则unclear。模型自报置信度和多模型多数票均不能自动批准。事实清晰但行业标准名不确定时保留原名，不能丢掉业务。

复用现有日志记录report/run、阶段、provider/model、request/attempt、提示词版本、输入输出token、耗时/费用、成功/失败/缓存命中及关联证据范围，不记录密钥。供应商不返usage记unknown并计入保守预算，不记0。资源按验收计划§7冻结，累计包含传输重试、修复、验证、预处理和导出；超限转缺项/限用并继续其他公司。

## 12. 指标、动作和标准化

已有度量及动作枚举继续复用；develops、produces、processes、sells、purchases、provides_service、operates 与数值分离。收入、成本、毛利、产能、产销存、加工量分属独立字段；字段扩展需要明确语义和代表证据，但不要求新增整套平台。

processing_volume 仅表示对外加工服务量，委外采购、内部工序和自营回收不能套用。未知动词可保留原文及候选解释，不新增未校验 canonical action。

## 13. 唯一主体政策

保留 subject_scope / subject_basis，无平行置信度或主体枚举。按局部证据依次判定：

1. 明确仅母公司/本公司单体为 issuer；具名子公司为 named_subsidiary；明确业务分部为 business_segment。局部更窄证据优先于报告封面集团表述。
2. 明确合并/集团为 consolidated_group + direct_source_wording。
3. 已完成同报告合并数值核对可为 consolidated_group + numeric_reconciliation_to_consolidated_statement，保留核对页和依据。核对不是普通事实接受前提。
4. 原文仅称“公司”或没有明确更窄范围，也没有主体冲突时，程序采用 consolidated_group + report_default_group_scope；保留原文，不伪装为直接合并证据。
5. 明确冲突、多主体不可区分或非本公司行动者无法归属时保持 unclear。默认规则不能把第三方行为改成上市公司行为。

同表局部证据可共享，不跨无关表传播。Gold、verify、行业合同和 projection 均采用本条；历史 Gold 冲突单列，不为当前接受强制把已支持的 group 降回 unclear。

### 13.1 Gold 主体判定顺序

先核对来源、物理锚点、对象、指标、数值/单位、期间和实际主体依据。存在这些错误或把明确更窄口径改为集团时，结果为 failed，不能被政策冲突覆盖。

仅当上述事实检查通过、默认集团 basis 合法且与历史 Gold 的主体预期不一致时，记 `gold_contract_conflict`，不计匹配通过，也不要求改 runtime 或历史 Gold。`allow_unclear_if_not_promoted` 中的 unsupported group 指违反现行主体规则的晋升，**不包括合法的 report_default_group_scope**。严格度规则只能在真实错误/政策冲突已区分后应用。

## 14. 数值、单位和比较

保留 source value/unit/header/qualifier 和原文存在的脚注；原文无脚注不制造。程序执行有限、有记录的等价转换，不按量级猜单位。duration、instant、event 分开；预计完工时间只进 qualifier，不覆盖 reported_period。重述列带 comparison_basis，与原公布数据并列。

相同量纲/对象/期间/口径才可比较；集团默认主体不自动使分部、抵消行、不同产品或不同 capacity_kind 可相加。历史事件单向等价仅限其已批准条件，不建任意模糊 matcher。

## 15. 错误处理与质量评价

关键数值/单位/期间/主体冲突、证据错绑、第三方行为混淆隔离到实际受影响记录。解析失败保留缺项，完整性不足不封锁无关记录。匿名身份保持 report-local，不能跨报告合并。仅合计披露不生成对手名称或 Relationship。

人工正常职责为抽样和冲突裁决，不是每家公司上线前逐条审批。缺乏证据的推断即使“概率较高”也不能当披露事实。

## 16. 全市场基础与行业增强

A 股通用基础包自动适用于全部行业。制造/材料、资源、能源公用、消费零售、一般服务、金融、医药、TMT 是增强家族，不是基础采集白名单。

行业增强只激活本报告可支持的指标；未经实现的增强记录未支持，仍交付基础骨架。行业目录未知、复杂业务组合或转型不剔除证券，先保留通用内容及增强待判定原因。

## 17. 按报告期分配增强包

复用现有正式分类作候选，以报告主要业务、板块和事件证据决定适用增强。原文主导业务和更窄分部优先；未知组合退回基础包，不能强套最近行业。没有已确认 regime 日期不阻止本报告基础画像，但不得回填历史生效日。

## 18. 行业研究与登记

独立行业文档定义指标、模板、触发、单位、正反例与小型验证；这是增强范围的验收，不是全行业基础采集前置审批。固定 Gold 只用于其版本回归；运行中发现新形态形成共性修复，不做无限公司专项补丁。

当前保留跨行业任务底座及制造/材料研究基线；真实LLM通用交付尚待新路线验收。行业增强按交付计划卡6后置，不再以旧M4轮次作为推进依据。文档登记或少数报告导出不等同全市场生产上线。

## 19. 单一执行链与任务

证券池/有效正式年报 → 增量入队 → 自动 Evidence → Stage 5 语义 owner → 记录接受/隔离 → 新契约持久化 → 骨架及商品关联 → 查询/画像/导出。

已发布入口 `company_profile_common_core`（preview、run、status、pause、resume、query、export）；旧 backfill / daily incremental / semantic repair / shadow_sync 名称在 CLI 与 Telegram 执行解析层被拒绝，不能当作已接 Stage 5。按时间/调用预算工作，默认结果复用；不要求指定公司、不要求凑齐50家。完成 scope 即保存，失败续跑不重复已经完成的 scope。

## 20. 产品暴露与有限供应链定位

通用版每家公司交付下列三个相连的视图，不以行业增强或完整知识图谱为前提：

| 视图 | 必需回答 | 按披露补充 |
| --- | --- | --- |
| 公司画像 | 主营、主要板块/产品服务、如何赚钱；主体/报告期与证据 | 规模、业务变化、经营指标 |
| 产品暴露 | 主要销售产品/服务及收入端关联、关键投入与成本端关联，区分自制/贸易/服务 | 金额、占比、采购依赖/集中度、商品映射 |
| 供应链定位 | 生产/加工/贸易/运营/服务等角色；明示上游投入、下游用途/渠道/客户类型 | 具名对手和关系、分部角色、多环节经营 |

产品服务不限于大宗商品：银行信贷、旅游服务、软件等也属于收入端对象。报告支持的业务抽象可由LLM归纳并引用证据；标准行业/商品映射歧义保留原名和待映射，不能按常识补客户名称或主张已建立交易关系。产品、业务线、投入项复用Segment/Activity/Measurement，角色与关联复用ValueChainRole/CommodityExposure的现有职责及必要版本化读取投影，不为三视图造三套存储。

商品输出保留业务对象、原名、标准标识或pending/ambiguous、角色、源record/Evidence引用、期间/知识时间、可用性。数量/金额依赖原Measurement；无披露不估算。程序确定映射标deterministic_derivation，LLM解释标生成方式和支持证据，不伪装直接披露。

同一商品可以同时为收入端、原料、能源或套保对象，分别呈现，不无依据净额化；销售端不代表净利润正相关，投入端不代表净利润负相关。行情序列未绑定不阻断已成立关联。不承诺净利润弹性、价格预测、传导/滞后或完整产业链。

每个视图有assessed/not_assessed/extraction_failed及已检查证据范围。读完相关披露后确实未披露的补充项可标not_disclosed；不适用有证据说明。不确定/冲突必须显示具体字段、原因、影响及恢复条件；“未发现明示关联”不等于零暴露。关键产品或核心角色未读/冲突，不能把公司整体判为可用。
