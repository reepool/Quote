# 公司画像分阶段验收计划

> 类型：requirements；版本：2（LLM主导纠偏）；制定：2026-10-16。
> 本文是后续公司画像验证的数量、质量、补救和进度唯一计划入口，细化产品总需求第27节；职责与交接仍遵循`ab_role_development_workflow.md`。
> 当前执行§7.46/B2卡§7.9，属于§7.44同一新增开发任务：浦发两项净收入金额已交，角色收口仍失败，A2当前不通过、可用1/4。最后6次物理余额改绑为同方、上汽现存证据的角色成稿/核验；修空正文发送和真实核验链丢失，不再同页空补源，不重开正式后继、不增加总额。

## 1. 目标与完成边界

目标是自动解读全部A股年报，为研究者交付公司画像、产品暴露和供应链定位，回答做什么、主要产品/服务及收入端关联、怎么赚钱、关键投入及上下游角色，并识别缺项/冲突。验收允许有限遗漏和可隔离错误，不要求每家公司所有附注行、经营指标及行业增强齐全。

通过本计划只意味着声明样本和审查范围内的受控研究交付可用，不等于全市场统计质量、DCF、交易或生产授权。生产保持`not_authorized`，`scale_quality_claim_allowed=false`；变更权限另作明确裁决。

累计分析过的公司数、修复后成绩、同一版本未见首发成绩分别报告。历史约70家公司是开发材料，不能折算成下一阶段的20家或100家。

## 3. 不可放宽的底线与可容忍项

底线是**已知错误不得作为确定事实对外使用**，不是承诺程序从不产生错误候选。错误候选可以被发现、拒绝或隔离；首次漏放仍计入原始错误及公司状态，不能靠补救抹掉。

以下属于底线问题：公司/子公司/交易对手错置；合并与母公司或本期与上期混淆；关键金额、单位、正负号错读；空格借额；否定、计划、注册许可误作当前经营；重大业务板块或变现机制被错误表述；缺来源却肯定作答；未运行或未检查冒充通过。

关键金额至少包括公司收入总额、主业务收入、主要板块金额及收入占比，另含会改变主要业务判断的交易金额。“小额”不豁免主体、期间、单位和方向正确性。底线问题先隔离有关对象及其依赖答案，必要时隔离整家公司；无关合法事实继续可查。

可以容忍：不影响主要业务判断的小额次要收入、个别非主要具名动作遗漏，来源确实未披露的补充字段，或有证据保留的歧义。不能容忍遗漏整个主要板块、用大量小记录掩盖主营缺失，或用`not_disclosed`掩盖未读、抽取失败、超时。

核验发现的次要错误也须修正或标为待核并退出确定结论；容错针对有限的首发错误和遗漏，不表示已知错误可以永久保留为可信事实。一处可局部处理的次要错误不要求整家公司隔离。

无法可靠补救时，交付说明必须写明公司/字段、来源页与版本、缺失或冲突原因、已经尝试的办法、受影响判断、使用限制及后续恢复条件。不猜数、不推法律全称、不从常识补角色；状态保持缺项、`unclear`或隔离。

## 4. 公司分级与评分口径

| 分级 | 判定 | 可交付内容 |
| --- | --- | --- |
| 可用 | 三维画像实质完整，主要板块、收入机制、主要产品暴露和供应链角色成立；已审核心召回≥90%，已审对象准确率≥98%；审查范围内无未处理的底线问题 | 有证据的画像；补充缺项和未核验范围仍显示 |
| 限用 | 部分维度/对象缺失、冲突或待核；可靠部分能独立成立，错误及依赖项已屏蔽 | 仅交付成立部分及具体限制；缺维度时`core_complete=false` |
| 隔离 | 入口未交付，或主体/主要业务/核心数字无法可靠区分，无法形成可信核心 | 状态、原因、原始证据及独立合法事实；不提供确定核心结论 |

“可用”不是所有字段已人工核过。等级同时记录首发和补救后两列；不能用手工写答案替代程序交付后标成自动可用。明确正确的源歧义处理若不影响三维核心，不必隔离整家公司。

### 4.1 冻结核心条件

独立读源后冻结每家核心条件，通常10–30项；该数量是控工作量的参考，不是截断重要披露的上限。必须覆盖三维实质回答、全部主要板块、变现机制、主要产品/服务的收入端与重要投入、供应链角色/上下游类型。每个视图分别列条件和召回，不允许表格多的公司或视图掩盖另一视图缺失。具名对手仅按重要性和披露选择，不默认把所有附注明细设为核心。已披露收入分项≥集团营业收入5%的板块均属主要板块；小于5%但原文明确列为主要业务的也不能省略。分项可比时覆盖累计≥90%的已披露业务收入构成；不可比、不分项或不同主体不强求相加，不编造分母。

主要数字、主体、期间、状态及原文冲突均全查。其他关联交易/出租细行等可列补充范围，不要求全量恢复才算三维可用。合同外实际输出仍在准确性审查范围，不能因未列正向条件而免责。

### 4.2 独立核验与统计

- 每家公司三视图（含三维画像）及其核心支持对象全部核原文；底线高风险对象全部核查。A不得以B的`accurate=true`或相同匹配器复算替代独立语义判断。
- 补充事实每家公司至少抽20个唯一实际对象，不足20则全查；按冻结种子分层选取，覆盖实际存在的收入/Measurement、Activity及其他对象类型，另外加查全部已发现疑点。S2至少400个补充对象，S3至少2000个；实际对象不足时据实报告，不重复计数凑数。
- 准确率＝核对正确的唯一对象/实际核对的唯一对象，核心、补充、疑点三组分列后去重合计，明确标“已审/抽样准确率”；未核验不得默认准确。发现错误即定向扩查同类输出，但不增样本公司。
- 核心召回＝满足的源合同核心条件/该公司全部核心条件；阶段指标采用逐公司召回率的算术平均，失败/未交付记0；同时报告每家公司、各层和微平均，防止表格多的公司淹没另一家失败。
- 四类主分层及交易所/行业的准确率、召回和可用率均展示。S2四类主分层每类最多1家首发不可用；S3四类主分层各自首发可用率≥80%、核心召回≥90%。不对只有一两家的行业子组机械要求百分比全过，但同类底线错误重复出现须扩查并处理。组内必需阶段指标未评估不算通过；没有交付对象的隔离公司准确率记不可评估，核心召回记0，不伪造准确率。
- 原始首发准确率、数字/语义错误、负例结果及后置修正各自保存。负例必须真实触发并实际评估；不能删除失败条件或用未发布宣称负例通过。

以下条件同时满足才通过；不以综合平均分抵销底线或整层失败。

| --- | --- | --- |
| 首发可用公司（未经修复） | ≥18/20 | ≥90/100 |
| 补救后可用公司 | ≥19/20 | ≥95/100 |
| 其余公司 | ≤1家，明确限用/隔离和说明 | ≤5家，明确限用/隔离和说明 |
| 首发核心召回宏平均 | ≥95% | ≥95% |
| 首发已审唯一对象准确率 | ≥99% | ≥99% |
| 补救后复核 | 修复版本仍满足上述召回/准确率及分层底线 | 同左 |
| 已知底线错误外放 | 0；有关事实和依赖答案已修正或屏蔽 | 0；同类受影响公司一并检查 |
| 实际负例 | 原首发通过率如实报告；最终可用/限用公司实际交付的全部适用负例已评估并通过 | 同左；隔离未发布公司记不可评估并占不可用名额，不能计负例通过 |
| 交付一致性 | 实际交付公司查询/导出/磁盘一致，失败完整可查 | 同左，并验证停止/续跑及同版本更新不重复写入 |
| 补救成本 | 需人工补救公司≤2；每家额外活跃补救≤30分钟 | 需人工补救公司≤10；每家额外活跃补救≤30分钟 |

三个视图的首发核心召回宏平均各须≥90%，合并仍须≥95%；全部主要板块已列入源条件。对不存在适用商品/具名对手的公司，正确的有据未披露是状态处理，不伪造正向事实或提高已审事实准确率。核心产品/角色无法判断仍为限用，不算可用。

初次观察不达≥99%准确率或≥95%宏召回，不能靠同源修复后分数把这一组改判首发通过。首发可用18家、补救后19家意味着允许在预算内补救及一家公司仍不可用；不要求所有补充披露100%召回。补救后各层使用同一适用底线核查，不能让新版本把原先可用公司修坏。

30分钟只限制额外人工补救，不混入常规独立审核、机器运行或等待；这些成本单列。S3另报告首次及复核的实际审核工作量，不将0业务token称为零开发/审核成本。成本记录无法还原时记未知，不能宣称通过补救成本指标。

## 6. 补救上限与数量到达后的裁决

1. 单家公司：优先通过既有来源补齐上下文/定向OCR或布局、一次有界LLM复读/验证；共性语义/结构修复后定向复核；额外业务重试最多1次、额外人工活跃补救最多30分钟。共性修复统一回归，不为每家公司建规则分支或手填事实。已到上限仍未解决则限用/隔离，附第3节说明。
2. 一组样本：全部首发观察完成后，最多2个共性修复迭代；每次只验证变动及直接回归，最终快照覆盖全组。先用离线局部检查完成至多两次共性修复，再以最终同版做每家公司至多一次正式后继；不得每改一次就用一次整组正式重跑。其他验证可复用已有原始证据只读核查；无法证明新版本端到端结果则不得宣称通过。需要再次重跑、超预算或无法隔离既有改动时交A裁决，不能自行续跑。
3. S2第一组20家达到数量即出结论。通过则进入下一阶段准备；不通过则集中处理最多3类主要根因，按上述上限修复，通过12家直接回归后，允许一次不同的新20家确认。第一组保留为失败及回归材料，不加入第二组的首发分数。
4. S2第二组仍失败：停止增加公司，S2结论为失败；列明确支持/不支持的披露类型、剩余根因和已知限制。选择收窄可用研究范围或重新规划，必须有新的A/用户范围裁决，不能增加第41家来稀释失败。
5. S3最多100家新公司，到100家即结论。允许上限内补救和同一100家复核；未达到首发门槛或补救后95家可用就不通过，不追加第101家。定位共性缺陷，提交失败说明及收窄范围/新方案，现有可靠研究事实继续可用。
6. 底线错误发现即停止受影响数据消费/标确定结论，扩查同一规则影响的公司；无关公司的隔离验证可继续。不能在未处理底线风险时启动下一阶段。失败不会自动触发整库清理、历史覆盖或生产变更。

S2主路径是20家，失败确认上限再20家；S3固定100家。因此历史12家之外正常需120家新样本，含一次S2确认最多140家。数量不是成功承诺，达到上限仍失败须明确结束该方案。

## 7. 真实LLM运行、预算与成本

新政策下开放语义必须真实调用公共LLM网关；field_id存在、PDF可读、测试使用fake或provider=None均不能算语义完成。语义缓存仅在完全相同的报告hash/输入范围/代码政策/模型/提示词版本且已有合格语义回执时可复用。L0/L1、S1新链及S2/S3首次语义验收必须各有真实调用；正式首次禁止复用语义输出，允许PDF解析缓存。显式开发修复接续按当前卡保兼容复验链，不算同版首发；以日志的request/attempt/model及实际usage核验，usage未知不得填0。

下列为新路线初始研发硬上限（不是实测性能或通用付费授权）；常规执行绑定现有可用模型或池、价格表/币种及费用计算方式。旧21入口均已结束；现行研发资源/真实次数只以§7.34的显式重分配为准。不在本规划指定供应商或新建gateway。常规每家公司一次完整尝试：从入口启动、registry、获取/解析、全报告导航/必要正文阅读、抽取/语义复核、内部重试到最后导出，绝对deadline≤900秒、输入＋输出token合计≤120000、实际物理请求（含失败/切换/verify）≤16次、费用≤人民币10元等值，任何一个到达即停止。预算在发请求前预留，未知usage按预留上限计；失败、模型切换和内部repair不重置预算。

2026-10-17计量裁决：120000约束的是有依据的输入＋输出token；UTF-8 payload字节＋framing是无法可信计量时的保守准入上界，不是实际usage或费用。允许在同一物理发送预算接点绑定与实际部署型号、分词器/计数接口及消息/schema封装相匹配的可核计量依据，保留依据版本、预留与实际usage；仅数正文、套同名模型、经验除数和fake usage均不合格。资料不足继续原保守上界；失败和unknown usage继续占预留，不能为跑通而清零。逐请求预留后允许用供应商返回的有效usage结算；静态全流程字节上界不等于实际token总量，不能仅因其超过120000而禁止§7.1的有界首家观察。常规资源验收仍须核模型/池、价格、容量及权限，不追改原失败。

## 9. S4全市场落地与日常容错

S3达标是样本内受控研究能力，不是几千家公司已达标；固定分层20/100也不是统计随机样本，不宣称全市场99%准确率。S4是必要产品终点，另行明确研究发布/生产任务授权，仍不启用DCF、交易和无依据价格敏感性。

1. 冻结时点全A股名单N及可得正式报告。所有N家公司100%有版本/处理状态；缺资产仍留N分母，走既有获取链，不能无限等待。相同版本已处理成果可复用但不算新的盲测。
2. 经批准按首波100、次波500、其余每波≤500运行；不要求全市场逐家人工冻结条件或验收。并发受现有provider配额、队列/机器容量约束，先实测再设置，不造新调度平台。单公司失败不终止其他公司，续跑不重复已完成相同工作。
3. 首次全量目标在启动后14个自然日内使N家公司全部具有终态或具体待资产说明；不是全部资料齐全。技术交付率＝得到持久化可查询分析结果（可用或限用）的公司/可读有效报告公司，须≥98%；仅任务报错/隔离状态不计交付。对全部N同时报告资产可得率、真实分析覆盖率及未交付数，禁止用可读分母隐藏缺资产。
4. 每波在观察前冻结随机种子，分层抽至少20家公司（不足20则全查），其中包含未复用新分析；每家核三视图核心与至少20个补充对象/不足全查。人工独立判断、同类错误扩查和分级定义沿§3–5。该波抽审首发可用率≥90%、补救后≥95%、核心宏召回≥95%、已审准确率≥99%、无已知底线错误外放；完整报告样本量/各层偏差，不把机器自评可用率替代人工实测。
5. 自动标记的可用/限用/隔离数量与人工抽审等级分开。失败或有冲突的核心项默认限用/隔离；对可单独屏蔽的次要错误只屏蔽事实与依赖答案。机器无法识别的错误仍可能存在，抽审只是有界检出，用户可反馈具体来源，由既有问题记录触发同类型追查和受影响scope后继更新。
6. 每家公司正式补救最多一次，人工活跃补救≤30分钟；每波需人工补救公司≤10%，超限视为共性能力缺口，停止扩大。已知底线错误立即停止受影响结论消费并扩查；样本质量不达标先停下一波、最多两次共性修复，最终一次同版复验仍失败则保留可靠部分、明确不支持的范围，不继续全市场发布。
7. 每波运行前按实测均值/P90、N/剩余量、并发及供应商价格计算日期/费用；累计费用上限必须明确授权，单公司仍沿§7。14日目标或预算不可达时先出资源/范围裁决，不自动加机器/费用。日常增量只处理新/更正的有效报告及受影响scope，目标为资产可用后P90≤24小时完成分析，单公司硬上限及失败补救不变。
8. 达到状态覆盖、技术交付、抽审质量、成本/时效和恢复验证，才可对具体N、版本及抽审范围声明全市场研究服务已交付；留下所有限用/隔离说明。不得将未解决的报告写成完整可信画像。
